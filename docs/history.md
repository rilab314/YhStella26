# 개정 이력

설계 문서의 변경 내역만 날짜순(최신이 위)으로 남긴다. 각 항목은 **무엇이 왜 바뀌었는지**만
짧게 적고, 바뀐 뒤의 설계 자체는 본문 문서에 있다. 본문에는 수정 이력을 쓰지 않는다
([design.md](design.md)의 작성 원칙).

## 2026-08-26 — 데이터셋 v1.1 → v1.2, 논문 산출물 생성 구조(15절) 신설

**데이터셋을 SEED-MAP v1.2 로 바꿨다** (사용자 지시). train 8,979장은 그대로고 val 1,282→1,218 ·
test 2,567→2,457 이다 — 타일이 196 m 정사각형인데 80~100 m 격자에 놓여 이웃끼리 절반 넘게
겹치는 탓에 split 경계에서 화면이 새고 있었고, 학습 타일과 겹치는 검증·시험 타일 174장을 뺐다.
v1.2 가 함께 지운 "타일 밖으로 완전히 나간 폴리라인"은 6.7.4 규칙 4가 이미 잘라 버리던
것이라 **로더 출력에 영향이 없다** — 라벨이 편집된 train 타일 1,205장을 양쪽으로 읽어 확인했다.
따라서 **GT 캐시를 다시 뜨지 않고, 과거 실행의 성적도 다시 재지 않는다**(사용자 판단).
재정리 스크립트는 `scripts/build_split_dataset.py`다.

**GSD 를 0.2550 m/px 으로 고쳤다.** 6.7절이 적고 있던 0.1278 은 **원해상도(1536 px) 타일
기준**이었고 우리가 쓰는 768 px 타일은 그 절반 크기라 값이 두 배다. 타일 지상 범위도
98 m → **195.8 m**. 교차 검증으로 차선 간격 중앙값 11.8 px × 0.255 = 3.01 m 가 실제 차로
폭과 맞는다(0.1278 이면 1.51 m). 미터 환산이 걸린 곳이 전부 이 값을 쓴다 —
`paper_outline.md` §7-② 가 이미 같은 결론을 내려 두었고, 설계 문서가 뒤늦게 따라간 것이다.

**논문 그림·표 생성 구조를 15절로 신설했다** (사용자 지시). 그림 14개·표 9개를 각각 별도
스크립트로 두고(`scripts/figures/`·`scripts/tables/`, 베이스도 같은 폴더), 정성 그림은
정량 조건으로 후보를 골라 **상한 100장**까지만
낸다. 출력은 저장소가 아니라 데이터 작업 폴더에 **폴더 단위로 지우고 다시 쓴다.**
현재는 스크립트에 설계(docstring)만 있고 구현은 없다 — 설계를 하나씩 검토한 뒤 구현한다.

## 2026-08-19 — 디코더 탐색 반경 24 → 12 → 5 (차선 갈아탐의 원인)

**반경을 정하는 것은 GT 간선 통계가 아니라 차선 간격이다.** 이웃 선까지의 중앙 거리가
11.8 px인데 반경 12셀(48 px)은 그 네 배라 옆 차선·옆 진입로의 정점이 후보로 들어왔다.
각도 게이트는 이것을 막지 못한다 — 앞 12셀에서 한 차선 옆은 각도로 14°뿐이라
정렬 게이트(18°)를 그냥 통과한다.

반경 5셀(20 px)로 줄이니 예측 점이 옆 선 위에 얹히는 비율이 **6.0% → 2.5%**, 전체 val
1,282장의 인스턴스 f1이 **0.3617 → 0.3933**이 됐다. GT 주입 천장은 0.9635 → 0.9441로 유지된다.
함께 정해지는 값들: `w_dist` 0.03 → 0.072(곱을 0.36으로 유지) · `min_points` 6 → 8
(종류별 평균 f1의 봉우리) · `merge_gap` 0 → 24(반경이 크던 시절에는 조각이 서로 겹쳐
"끝점이 가깝고 마주봄" 조건에 걸리지 않았다).

**`max_turn_deg`는 45로 남긴다.** 실측한 99% 분위수는 26.6°지만 그 값을 걸면 GT 주입
천장이 0.9612 → 0.9561로 깎이고 모델 성능은 오르지 않는다 — 정렬 게이트가 이미 같은 것을
재고 있다. 4 px 격자 위에서 각도를 재면 양자화 계단 때문에 실제보다 훨씬 나쁘게 나오므로,
꺾임각은 반드시 **디코딩 결과**로 재야 한다(`scripts/turn_angles.py`).

## 2026-08-11 — 디코더 탐색 반경 2 → 24

`DecodeConfig.radius` 기본값을 실측으로 다시 정했다. 2는 **GT 간선 통계**(98.7%가 1칸)에서
나온 값인데, 그 통계는 **정점 재현율 100%를 전제**한다. 실제 모델은 GT 셀의 ~44%만 정점으로
만들어 이웃한 두 셀이 둘 다 예측되는 일이 드물고, 디코더가 그 빈칸을 건너뛰어야 한다.
반경을 24로 넓히니 같은 예측에서 f1이 0.2173 → 0.3589(+65%)로 올랐다.

## 2026-08-10 — CPU 예산을 config로 옮김

프로세스가 쓸 코어 수와 스레드 수를 `CpuConfig` 한 곳에서 정하고, 진입 직후 `CpuBudget.apply()`가
건다. torch가 프로세스마다 코어를 전부 잡던 것이 원인으로, 학습 arm이 겹치면 부하가 튀어
같은 기계를 쓰는 사람이 불편했다. 부하 상한을 쫓는 대신 **쓸 코어를 미리 떼어 두는 방식**이다.
`reserved_cores`만큼은 항상 사람 몫으로 남는다.

## 2026-08-10 — focal $\alpha$ 기본값 0.25 → 0.75

히트맵 focal의 $\alpha$를 통상값 0.25에서 0.75로 올렸다. 놓친 정점은 폴리라인 하나를 통째로
없애므로 거짓 양성보다 비싸다는 것이 근거이고, U 규격 실측에서 f1 +22.4%(heat_recall
0.8286 → 0.9545)로 확인했다. 같은 라운드에서 `heatmap_thresh`·`dilate`·`select_mode` 손잡이도
각각 +10~18%였으나, 손잡이끼리의 조합은 아직 시험하지 않아 기본값은 $\alpha$만 옮겼다.

## 2026-08-10 — 클래스 CE에 클래스별 가중 벡터

클래스 손실이 스칼라 두 갈래(가중 있음/없음) 대신 **클래스별 가중 벡터** 하나를 받도록 했다.
`class_bg_weight`는 그 벡터의 배경 성분으로 흡수됐고, 전경 성분을 만드는 `class_freq_power`가
새로 생겼다. 희소 클래스 3종이 검증 200장에서 한 번도 예측되지 않은 관측이 계기다.
전경 성분을 평균 1로 정규화해 `power`를 키워도 손실 스케일이 변하지 않게 했다.

## 2026-08-07 — target을 모델 출력 형태로, 디코더 시드 변경, $R = 2$ 고정

같은 날 이어진 개정이다. 첫 실데이터 학습(F1 0.066)에서 드러난 **구조적 조각남**의 원인을
찾아 인코딩·디코딩을 함께 다시 설계했다.

**인코딩·디코딩 재설계 — "선 하나 = 사슬 하나".** GT를 완벽히 주입해도 인스턴스 F1이
0.63~0.69에 막히는 원인이 **인코딩(클래스 단위 그래프)과 디코딩(그래프 절단)의 비대칭**임을
실측으로 확인했다.

- GT를 **선(인스턴스) 단위 사슬**로 인코딩 — 셀당 분기 항상 2, 끝칸 미채움, 3×3 순위 규칙으로
  지그재그·고립 노드 제거.
- 연결 방향의 원점을 셀 중심에서 **자기 노드 점**으로 변경.
- 슬롯 종점 라벨 $t$를 폐기하고 **`end_map` 직접 감독**으로 대체.
- 디코더를 그래프 절단에서 **사슬 확장**(마주봄 확인, 탐색 반경 2)으로 교체.
- 재구현 실측 반영 — `n_max` 9500, `window_size` 7 + 윈도우 층 gradient checkpointing,
  전체 train 8,979장 통계, `category_id` 표 확정, `switch_rate` → `match_ambiguity` 개명.

**target을 모델 출력과 같은 형태로.** "GT는 사실만 저장하고 방향은 criterion이 유도한다"는
방침을 뒤집었다 — 분기가 항상 2로 고정되면서 간접층이 값을 못 하게 됐기 때문이다.
인코더가 **연결 방향 2개를 직접 저장**(`conn_dirs`)하고, `conn_cells`·`end_point`와
criterion의 유도 계산을 없앴다.

**디코더 시드와 클래스 관리 변경.** 시드를 끝 셀에서 **클래스 확률 국소 피크**로 바꾸고
거기서 양방향으로 확장한다. 확장 게이트에 사슬 클래스 확률 하한을 두고, 완성된 사슬은
**순도 검사**를 통과해야 남는다.

**연결 슬롯 $R = 2$로 고정** (사용자 결정). GT 분기 수와 일치시킨다 — Y자 분기도 두 인스턴스로
찾으면 되므로 셀 하나가 세 방향을 낼 필요가 없다. $R = D = 2$가 되면서 매칭 순열이 2개로 줄었다.

## 2026-08-04 이전 — 초기 설계

이 저장소가 만들어지기 전에 쓰인 부분이다. 개정이 여러 차례 있었으나 **정확한 날짜 기록이
남아 있지 않다** — 문서가 외부에서 완성된 상태로 들어왔고, 그전 작업 기록이 이 저장소에도
로컬 세션 기록에도 없다. 내용상 굵직한 변화만 정리하면 다음과 같다.

- **GT 표현 단순화** — GT를 self 정보 맵(class/coord/end) + 연결 이웃 셀 좌표로 줄이고,
  방향·$t$ 텐서는 criterion이 유도하도록 했다. 학습 노드 선택을 "GT 양성 ∪ 예측 히트맵 마스크"로,
  매칭 비용을 방향 정렬 + 존재 확률로 정리했다.
- **조립 방식 확정** — 클래스 선택을 config의 `path`+`name` 문자열과 단일 관문 `build_instance`로
  확정하고(자동 registry 폐기), `from_cfg(module_cfg, cfg, **kwargs)` 시그니처와
  `check_all(cfg)` 사전 검증을 도입했다. 실행 재현은 소스 전체 복사로 정했다.
- **실데이터 파이프라인 추가** — SEED-MAP 라벨 JSON 구조 분석, 학습 클래스 확정(11종 + 배경),
  `LINE_STRING`만 사용, 타일 경계 자르기(전체 점의 49.8%가 이미지 밖).
- **손실 모듈화·로깅·디코딩 신설** — 손실을 3모듈 + 조립으로 분해하고 가중치를 최하위 항목마다
  하나씩 단일 층으로 뒀다. 백본을 3층 구조로, 에폭 단위 로깅과 시각 로그를 추가했고,
  객체 생성(디코딩) 절을 새로 세웠다.
- **GT 인코더 재설계** — GT 노드를 인스턴스 단위 대표점에서 **픽셀 무게중심**으로 바꿨다.
  이중선을 두 인스턴스로 라벨링한 실데이터에서 노드가 갈라지지 않게 하려는 것이었다.
- **평가 지표 신설** — 얇은 선에 맞는 **비대칭 버퍼 CCQ**(커버리지 관대 / 정확성 엄격)를 주
  지표로 설계하고, 보조로 집계 커버리지·RMS 횡오차·GT당 조각 수를 뒀다. FP를 중복/환각으로
  분해했다. 디코더·평가 지표를 학습 루프보다 앞으로 옮겼다.

## 2026-08-12 — 디코더 비용 함수 교정 (f1 0.3600 → 0.4804)

탐색 반경을 2 → 24로 키운 뒤(08-11) **그 값을 전제로 정해졌던 다른 값들을 다시 재지 않아**
성능이 3분의 1가량 묻혀 있었다. 세 가지를 실측으로 고쳤다.

- **`decode.w_dist` 0.001 → 0.03** (최대 개선). 후보 비용의 거리 항이 반경 2 시절의 동률
  해소용 상수(`DISTANCE_TIEBREAK`)로 **모듈에 박혀 있어 스윕 대상에조차 오르지 않았다.**
  반경 24에서 최대 기여 0.034는 정렬 항(0~0.3) 앞에서 무시돼 **디코더가 정점을 건너뛰며
  20셀을 도약했고**, 이것이 한 선을 4~5조각으로 쪼갠 주원인이었다. config로 뺐다.
  캐시 4개·200장에서 f1 +33% · 정밀도 +64% · `chain_len` +130% · `frag` −38%로 일정하다.
- **`decode.exist_thresh` 0.5 → 0.3.** 사슬의 27%가 "연결 없음" 예측에 끊기고 있었다
  (GT 주입은 0%). 0.3에서 `stop_exist` 0.268 → 0.001, `chain_len` +40%.
- **`decode.align_thresh` 0.7 → 0.85.** 거리 항이 죽어 있는 동안에는 각도를 조이면 손해였다.
  거리를 물리자 0.85~0.9가 평평한 최적이 됐다(+4.7%).

`radius`(24)·`opp_thresh`(0.7)·`min_class_prob`(0.1)은 새 작동점에서도 최적이라 유지한다.
`align_mode="perp"`·`seed_mode="end_peak"`·`stop_needs_nocand=True`는 모두 기각됐다 —
문제는 게이트가 아니라 **비용 함수가 거리를 안 보는 것**이었다.

10.3절의 "거리 항은 해로웠다(`w_dist=0.3` → 간선 정확도 0.985 → 0.953)"는 **반경 2에서 잰
값**이므로 무효다. 문서를 정정했다.

게이트에 불변식 검사 종류(`invariant`)를 추가하고 `w_dist × radius >= 0.3`을 걸었다 —
반경을 다시 키울 때 거리 항을 같이 보게 강제한다.
