# 개정 이력

설계 문서의 변경 내역만 날짜순(최신이 위)으로 남긴다. 각 항목은 **무엇이 왜 바뀌었는지**만
짧게 적고, 바뀐 뒤의 설계 자체는 본문 문서에 있다. 본문에는 수정 이력을 쓰지 않는다
([design.md](design.md)의 작성 원칙).

## 2026-08-10 — 클래스 CE에 클래스별 가중 벡터

클래스 손실이 스칼라 두 갈래(가중 있음/없음) 대신 **클래스별 가중 벡터** 하나를 받도록 했다.
`class_bg_weight`는 그 벡터의 배경 성분으로 흡수됐고, 전경 성분을 만드는 `class_freq_power`가
새로 생겼다. 희소 클래스 3종이 검증 200장에서 한 번도 예측되지 않은 관측이 계기다.
전경 성분을 평균 1로 정규화해 `power`를 키워도 손실 스케일이 변하지 않게 했다.

## 2026-08-10 — 문서 분할과 이력 분리

한 파일 2,551줄이던 설계 문서를 주제별로 나눴다. `design.md`는 색인과 작성 원칙만 맡고,
본문은 [structure](structure.md)·[data](data.md)·[model](model.md)·[pipeline](pipeline.md)·
[decisions](decisions.md) 다섯 파일로 갈랐다. 절 번호(1~14)는 상호 참조를 지키려고 그대로 뒀다.

- 본문 전체에서 "N차 개정" 표기를 걷어내고 현재 상태 서술로 바꿨다. 폐기된 대안은
  "왜 그 방식을 쓰지 않는가"라는 근거로만 남겼다.
- 존재하지 않는 `architecture.md` 참조를 제거했다(관련 결정 항목도 함께 삭제).
- 완료된 일을 미래형으로 적은 문장을 현재형으로 고쳤다.

## 2026-08-09 — 계획서에서 설계 문서로 전환

파일명을 `impl_plan.md`에서 `design.md`로 바꾸고 git 추적 대상으로 전환했다. 계획서가 아니라
설계서이고, 코드와 함께 버전 관리되어야 하기 때문이다. 미래형 서술을 현재형으로 고치면서
코드와 어긋난 곳을 실측으로 맞췄다.

- 코드에는 있는데 문서에 없던 모듈을 반영 — `eval/cellstat.py`(셀 단위 진단 지표, 11.5절),
  `decode/stats.py`(디코더 정지 사유 카운터, 10.6절), `decode/`의 `vertices`·`postprocess`·
  `cache`·`sweep` 분리(10.1절), `config_io.py`(4.3절), `model/inject.py`(7.1절).
- 정정 — 4.1절 config 스키마를 실제 기본값으로(기본 백본 ConvNeXtV2-base, neck FPNLite,
  누락 필드 20여 개), 9.3절 체크포인트 감시 지표가 `val/total`이 아니라 `val/inst/f1`,
  11.1절 매칭이 최대가중이 아니라 그리디 근사, 6.4.1절 인코딩 시간 70 ms → 18.2 ms.
- 신설 — 10.4절 조각 병합(`ChainMerger`), 10.6절 사슬 신뢰도(사슬 평균 48.2셀이므로 링크
  성공률 0.99가 목표라는 계산), 11.1절 "알려진 한계"(버퍼 12 px가 차선 간 거리 중앙값과 같아
  `correctness`가 무력하다 — 판정은 `f1`·`coverage`로 한다), 11.5절 셀 진단 지표 22종.
- 12절 마일스톤을 M0~M14 전부 완료로 표시하고, 14절은 DINOv3 게이트 승인만 열린 항목으로 정리.

## 2026-08-07 — target을 모델 출력 형태로, 디코더 시드 변경, $R = 2$ 고정

같은 날 이어진 개정이다. 첫 실데이터 학습(F1 0.066)에서 드러난 **구조적 조각남**의 원인을
찾아 인코딩·디코딩을 함께 다시 설계했다.

**인코딩·디코딩 재설계 — "선 하나 = 사슬 하나".** GT를 완벽히 주입해도 인스턴스 F1이
0.63~0.69에 막히는 원인이 **인코딩(클래스 단위 그래프)과 디코딩(그래프 절단)의 비대칭**임을
실측으로 확인했다.

- GT를 **선(인스턴스) 단위 사슬**로 인코딩 — 셀당 분기 항상 2, 끝칸 미채움, 3×3 순위 규칙으로
  지그재그·고립 노드 제거.
- 연결 방향의 원점을 셀 중심에서 **자기 노드 점**으로 변경.
- 슬롯 종점 라벨 $t$를 폐기하고 **`end_map` 직접 감독**으로 대체.
- 디코더를 그래프 절단에서 **사슬 확장**(마주봄 확인, 탐색 반경 2)으로 교체.
- 재구현 실측 반영 — `n_max` 9500, `window_size` 7 + 윈도우 층 gradient checkpointing,
  전체 train 8,979장 통계, `category_id` 표 확정, `switch_rate` → `match_ambiguity` 개명.

**target을 모델 출력과 같은 형태로.** "GT는 사실만 저장하고 방향은 criterion이 유도한다"는
방침을 뒤집었다 — 분기가 항상 2로 고정되면서 간접층이 값을 못 하게 됐기 때문이다.
인코더가 **연결 방향 2개를 직접 저장**(`conn_dirs`)하고, `conn_cells`·`end_point`와
criterion의 유도 계산을 없앴다.

**디코더 시드와 클래스 관리 변경.** 시드를 끝 셀에서 **클래스 확률 국소 피크**로 바꾸고
거기서 양방향으로 확장한다. 확장 게이트에 사슬 클래스 확률 하한을 두고, 완성된 사슬은
**순도 검사**를 통과해야 남는다.

**연결 슬롯 $R = 2$로 고정** (사용자 결정). GT 분기 수와 일치시킨다 — Y자 분기도 두 인스턴스로
찾으면 되므로 셀 하나가 세 방향을 낼 필요가 없다. $R = D = 2$가 되면서 매칭 순열이 2개로 줄었다.

## 2026-08-04 이전 — 초기 설계

이 저장소가 만들어지기 전에 쓰인 부분이다. 개정이 여러 차례 있었으나 **정확한 날짜 기록이
남아 있지 않다** — 문서가 외부에서 완성된 상태로 들어왔고, 그전 작업 기록이 이 저장소에도
로컬 세션 기록에도 없다. 내용상 굵직한 변화만 정리하면 다음과 같다.

- **GT 표현 단순화** — GT를 self 정보 맵(class/coord/end) + 연결 이웃 셀 좌표로 줄이고,
  방향·$t$ 텐서는 criterion이 유도하도록 했다. 학습 노드 선택을 "GT 양성 ∪ 예측 히트맵 마스크"로,
  매칭 비용을 방향 정렬 + 존재 확률로 정리했다.
- **조립 방식 확정** — 클래스 선택을 config의 `path`+`name` 문자열과 단일 관문 `build_instance`로
  확정하고(자동 registry 폐기), `from_cfg(module_cfg, cfg, **kwargs)` 시그니처와
  `check_all(cfg)` 사전 검증을 도입했다. 실행 재현은 소스 전체 복사로 정했다.
- **실데이터 파이프라인 추가** — SEED-MAP 라벨 JSON 구조 분석, 학습 클래스 확정(11종 + 배경),
  `LINE_STRING`만 사용, 타일 경계 자르기(전체 점의 49.8%가 이미지 밖).
- **손실 모듈화·로깅·디코딩 신설** — 손실을 3모듈 + 조립으로 분해하고 가중치를 최하위 항목마다
  하나씩 단일 층으로 뒀다. 백본을 3층 구조로, 에폭 단위 로깅과 시각 로그를 추가했고,
  객체 생성(디코딩) 절을 새로 세웠다.
- **GT 인코더 재설계** — GT 노드를 인스턴스 단위 대표점에서 **픽셀 무게중심**으로 바꿨다.
  이중선을 두 인스턴스로 라벨링한 실데이터에서 노드가 갈라지지 않게 하려는 것이었다.
- **평가 지표 신설** — 얇은 선에 맞는 **비대칭 버퍼 CCQ**(커버리지 관대 / 정확성 엄격)를 주
  지표로 설계하고, 보조로 집계 커버리지·RMS 횡오차·GT당 조각 수를 뒀다. FP를 중복/환각으로
  분해했다. 디코더·평가 지표를 학습 루프보다 앞으로 옮겼다.
