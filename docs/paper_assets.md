# 15. 논문 산출물 — 그림·표 생성 구조

논문에 실릴 **그림 14개와 표 9개를 어떻게 만드는가**의 설계다. 그림·표의 *내용*(무엇을 그리고
무엇을 싣는가)은 `paper_outline.md` 3·4절에 있고, 이 문서는 그것을 **어떤 구조로 생산하는가**를
정한다. 구현은 `scripts/figures/`·`scripts/tables/`에 있다.

---

## 15.1. 왜 산출물마다 스크립트를 두는가

**그림 하나 = 스크립트 하나, 표 하나 = 스크립트 하나.** 손으로 만든 그림·표는 논문에 넣지 않는다.

이유가 셋이다.

1. **실험은 계속 바뀐다.** 개선 루프가 도는 동안 파라미터가 바뀌고 실행이 늘어난다. 손으로
   옮겨 적은 표는 그때마다 다시 옮겨 적어야 하고, **한 번은 반드시 틀린다.**
2. **"이 값은 어디서 나왔나"에 답할 수 있어야 한다.** 심사에서 반드시 받는 질문이고,
   산출물마다 스크립트가 있으면 그 질문의 답이 곧 파일 경로다.
3. **그림 고르기가 재현 가능해야 한다.** 정성 그림을 눈으로 골랐다면 "잘 된 것만 골랐다"는
   비판에 답할 말이 없다. 조건을 코드로 적어 두면 그 조건 자체를 캡션에 쓸 수 있다.

이 방침의 대가는 **개념도까지 코드로 만들려는 유혹**이다. 그러지 않는다 — 블록 다이어그램의
도형은 그리기 도구로 만든다. 다만 **그림에 적을 숫자는 코드로 뽑는다**(15.3절 마지막).

## 15.2. 폴더 구조와 출력 규약

```
scripts/figures/
├── figure_base.py    SampleFigure(샘플 선별형) · PlotFigure(집계형) + 출력 경로 규약
└── figure_01.py ~ figure_14.py

scripts/tables/
├── table_base.py     PaperTable(csv + markdown) + 출력 경로 규약
└── table_01.py ~ table_09.py     (논문 Table I~IX)
```

**베이스는 같은 폴더에 둔다.** `python scripts/figures/figure_01.py` 로 실행하면 파이썬이
그 스크립트의 폴더를 알아서 경로에 올리므로 `import figure_base` 가 그대로 된다 —
`sys.path` 를 건드리지 않는다(CLAUDE.md).

그 대가는 하나다. **`PAPER_ROOT` 문자열이 두 베이스에 각각 있다** — `scripts/` 는 패키지가
아니라 두 폴더가 서로를 import 할 수 없기 때문이다. 상수 하나뿐이라 이 중복이 폴더를
하나 더 만드는 것보다 싸다고 봤다. **경로를 바꾸면 두 곳을 함께 고친다.**

**출력은 저장소가 아니라 데이터 작업 폴더에 쌓는다.**

```
.../Ongoing/2026_stella/paper/
├── figure/figure_01/  001_{타일id}_{점수}.png ...   (최대 100장)
└── table/table_01/    table_01.csv · table_01.md
```

그림은 실행마다 수백 MB가 새로 만들어진다 — git 이력에 넣을 것이 아니다.
**논문에 실제로 고른 몇 장만** `docs/figures/`로 옮겨 커밋한다.

### 덮어쓰기는 폴더 단위다 (사용자 지시)

`figure_01`을 다시 그리면 `figure/figure_01/`을 **통째로 지우고 새로 만든다.**
파일 하나씩 덮어쓰면 사고가 난다 — 지난 실행에서 3위였다가 이번 실행에서 조건을 통과하지
못한 그림이 그대로 남아 "이번 결과"에 섞인다. 지우는 단위는 **산출물 하나**이므로
다른 그림 폴더는 건드리지 않는다.

### 이름은 두 자리 0 채움

그림이 14개라 `figure_1`과 `figure_14`가 이름순으로 붙어 버린다. `figure_01`~`figure_14`,
`table_01`~`table_09`로 쓰고, 논문의 로마숫자 표 번호(Table I~IX)에 1:1 대응시킨다.

## 15.3. 그림 — 세 갈래

| 갈래 | 무엇 | 출력 | 해당 그림 |
| --- | --- | --- | --- |
| **샘플 선별형** | 샘플마다 조건을 재고 통과한 것만 그린다 | 최대 100장 | 1 · 4 · 7 · 9 · 11 · 12 |
| **집계형** | 데이터 전체를 집계해 그래프 한 장 | 1장 + csv | 2(c) · 3 · 5(c) · 6 · 8(c) · 10 · 13 · 14 |
| **개념도** | 그리기 도구로 만든다 | — | 2(a,b,d) · 3의 도형 · 5(a,b) · 7의 도형 · 8(a,b) |

### 샘플 선별형의 규약

**데이터 전체를 렌더링해 눈으로 고르지 않는다.** 그림마다 *그 현상이 실제로 일어난 프레임만*
정량 조건으로 고르고, 정렬 기준과 상한을 둔다.

1. **상한 100장** (사용자 지시). 사람이 100장까지는 넘겨 보고 고를 수 있다.
   조건이 그보다 훨씬 많이 통과하면 **조건이 헐거운 것**이므로 조건을 조인다.
2. **파일명 앞 세 자리가 순위다.** 뒤에 타일 id 와 판정 수치를 붙여, 파일 이름만 보고
   왜 뽑혔는지 알게 한다 — `003_126.6219,37.3851_f1-742.png`.
3. **무엇으로 정렬했는지 스크립트 docstring 첫 문단에 쓴다.** 그 문장이 논문 캡션이 된다.
4. **이미지는 한 번만 만든다.** 조건 판정 중에 완성 이미지를 메모리에 인코딩해 두고,
   상위 100장만 디스크에 쓴다. 조건 판정과 렌더링을 두 번 돌리지 않는다.
5. **렌더링 규칙을 모두가 공유한다.** 예측이든 GT 든, 우리 것이든 baseline 것이든 같은
   함수로 그린다 — 그래야 그림의 차이가 알고리즘의 차이로 읽힌다. 클래스 색 폴리라인 +
   **양 끝점 흰 테두리 원**. 끝점 원이 이 논문의 장치다: 선만 그리면 한 차선이 네 조각
   났는지 안 보이지만, 끝점 원을 찍으면 **조각남이 눈으로 세진다.**

### 집계형의 규약

1. **그린 값을 반드시 CSV 로 같이 남긴다.** 그림의 숫자와 본문의 숫자가 어긋나는 사고는
   논문에서 가장 자주 나온다. CSV 가 있으면 본문을 쓸 때 그것을 보고 옮긴다.
2. **표가 이미 그 값을 갖고 있으면 표의 CSV 를 읽는다.** 다시 계산하지 않는다 —
   표와 그림이 어긋날 수 있는 경로 자체를 없앤다.
3. **PNG 와 PDF 를 같이 낸다.** IEEE 는 벡터 그림을 요구한다.
4. **폭을 미리 정해 그린다** — 1단 3.5 in, 2단 7.16 in. 그려 놓고 줄이면 글자가 안 읽힌다.

### 개념도도 숫자는 코드로 뽑는다

블록 다이어그램의 텐서 크기(Fig. 3), 각도 섹터의 채널 인덱스(Fig. 2c)를 손으로 적으면
config 를 바꿨을 때 **그림이 조용히 틀린 값을 갖게 된다.** 도형은 그리기 도구로 만들되,
그 위에 적을 숫자는 스크립트가 CSV 로 뽑아 둔다.

## 15.4. 표 — 값의 출처를 하나로

| 출처 | 무엇 | 읽는 곳 |
| --- | --- | --- |
| 학습 로그 | 실행별 val 지표 | `stella/eval/runlog.py` |
| 예측 캐시 | 디코더 설정을 바꿔 다시 잰 지표 | `stella/decode/sweep.py` |
| 라벨 JSON | 클래스 빈도·길이 분포 | `scripts/stat_labels.py` |
| config | 파라미터 값 | `configs/` dataclass 를 직접 읽는다 |
| 코드 | 텐서 shape·dtype | `stella/model/stella.py`의 출력 계약 |
| 손으로 | 관련연구 비교 매트릭스 | 스크립트 안의 상수 표 |

**읽는 곳을 하나로 두는 것이 핵심이다.** 표가 `metrics.csv`를 직접 파싱하면 판정
스크립트(`scripts/judge_round.py`)와 값이 갈라진다 — 논문의 숫자와 실험 판정의 숫자가
다른 상황을 만들면 안 된다.

**사람이 정하는 값도 스크립트에 둔다.** Table I(표현 방식 비교)처럼 저자의 문헌 판단으로
채우는 표도 내용을 스크립트 안의 상수 표에 두고 렌더링만 코드가 한다 — "어느 파일을
고치나"가 하나로 남는다.

### 그 밖의 규약

- **두 파일을 낸다.** `.csv`는 기계용(그림이 읽는다), `.md`는 원고에 붙여 넣는 용도.
  둘의 숫자는 같은 형식화를 거친 같은 값이다.
- **빈칸은 `–`(en dash).** 0 과 "아직 안 쟀음"이 같은 칸에 보이면 안 된다.
- **실험이 아직 없으면 빈 표를 내고 무엇이 없는지 출력한다.** 스크립트가 죽으면 안 된다.
- **규격이 다른 실행의 절대값을 한 표에 섞지 않는다.** U 규격(3,000장·10에폭)과 F 규격
  (전체 데이터)은 데이터 3배 차이로 F1 이 14%쯤 난다. 섞어야 할 때는 블록을 나누고
  각 블록에 규격을 명시한다 (Table VIII 이 그런 경우다).

## 15.5. GPU 를 쓰지 않는다

입력은 `scripts/dump_predictions.py`가 떨군 **예측 캐시**다. 한 번 떨궈 두면 그 뒤로는
CPU 만으로 그림·표를 만들 수 있어, **학습이 GPU를 다 쓰는 동안에도 논문 작업이 돌아간다**
(D 트랙 규약). 학습 중에는 CPU 부하 상한 16을 지킨다.

부수 효과가 하나 더 있다 — 그림과 표가 **같은 캐시·같은 디코더 설정**을 읽으므로,
"표에서 본 F1 을 그림에서 눈으로 확인한다"가 성립한다. 값이 갈라질 경로가 없다.

### split 을 그림마다 고른다

방법 설명용 그림(Fig. 1·4·6·7)은 **val**, 결과용 그림(Fig. 9·11·12)과 결과 표는 **test** 다.
논문이 수치를 보고하는 split 과 그림이 어긋나면 안 된다.
