# STELLA 설계 문서

**위성/항공 타일 영상(768×768)에서 차선(도로 노면 선형 객체)을 검출하는 딥러닝 모델의 설계 문서다.**
핵심은 **토큰 기반 연결성 출력 헤드** — 셀마다 self 토큰 1개와 연결 슬롯 $R$개를 두고, 연결 슬롯이
"이 셀에서 선이 어느 방향으로 이어지는가"를 예측하면 디코더가 그 방향들을 사슬로 엮어 클래스별
폴리라인(line string) 인스턴스를 만든다. GT 인코딩과 디코딩이 **같은 모양**(선 하나 = 사슬 하나)
이라는 것이 이 설계의 중심 아이디어다.

**파이프라인 구현은 끝났고 지금은 개선(실험) 단계다.** 현재 성능(백본 ConvNeXtV2-base 기준 —
DINOv3는 HF 게이트 승인 대기, 14절): **GT 주입 인스턴스 F1(파이프라인 천장) 0.976**,
**학습 모델 인스턴스 F1(SEED-MAP val, 40에폭) 0.199**. 실험 계획·결과는 `experiment/`에 쌓이고,
개선 루프 운영 규약은 `.claude/skills/improve-loop/SKILL.md`에 있다 — 이 문서와 역할이 다르다.
이 문서군은 "무엇을 어떻게 설계했나", 개선 루프 문서는 "무엇을 어떻게 실험하나"다.

이 문서군이 설계의 단일 출처다. 코드와 어긋나면 둘 중 하나를 고쳐 맞춘다.

## 문서 작성 원칙

1. **본문은 현재 최신 상태만 서술한다.** "몇 차 개정에서 바뀌었다", "이번에 추가했다" 같은
   수정 이력을 본문에 남기지 않는다. 읽는 사람에게 필요한 것은 지금 유효한 설계 하나다.
2. **폐기된 대안은 근거로서만 언급한다.** "A 방식은 이러이러한 문제가 있어 쓰지 않는다"는
   현재 선택의 이유이므로 남긴다. 언제 그렇게 바뀌었는지는 쓰지 않는다.
3. **변경 내역은 [history.md](history.md)에만** 날짜순으로 짧게 요약한다. 차수가 아니라
   **날짜**가 기준이다.
4. **실측이 설계값과 다르면 실측을 따른다.** 바뀐 값은 config에 근거를 주석으로 남긴다.
   `n_max`·`max_conn_dist`·`w_dist`가 그렇게 정해졌다.
5. **파일은 주제별로 나누고, 절 번호는 문서를 옮겨도 유지한다.** 상호 참조가 "6.4절" 형태로
   문서 전체에 퍼져 있으므로 절 번호를 다시 매기지 않는다. 어느 번호가 어느 파일에 있는지는
   아래 색인이 알려준다.
6. 문서·주석·대화는 한국어로 쓴다.

## 먼저 알아야 할 규약

문서 어디서나 전제되는 것들이다. 자세한 정의는 각 문서의 해당 절에 있다.

- **좌표.** 셀 인덱스만 $(i, j)$ = (행, 열)이고, **그 외 모든 2차원 벡터는 $(x, y)$ 순서**다.
  셀 내 좌표의 원점은 셀 좌상단, 연결 방향의 원점은 자기 노드 점이다 (6.1절).
- **기호.** $B$는 언제나 배치, $L = 192$는 격자 한 변, $R = 2$는 연결 슬롯 수,
  $K = R + 1 = 3$은 노드당 토큰 수, $D = 2$는 셀당 GT 분기 수다 (6.1절).
- **GT와 모델 출력은 같은 형태다.** 같은 격자, 같은 항목, 같은 개수 — 남는 차이는 슬롯 순서뿐이고
  그것은 매칭이 배정한다 (6.2·7.1절).
- **조립.** `__init__`은 config를 모르고, 클래스 선택은 `build_instance` 한 곳에서만 하며,
  최상위 배선은 `stella/train/train.py` 한 곳에 있다 (5절).
