# STELLA 개선 루프 — 운영 규약 + 방법론

**이 문서가 단일 출처다.** 무엇을 어떻게 재고 판정하는지(방법론)와 누가 어떻게 돌리는지(운영)를
한 곳에 둔다. 나머지 둘은 역할이 다르다.

| 문서 | 무엇 | 갱신 시점 |
| --- | --- | --- |
| **이 문서** | 방법·규칙·자원 — "어떻게 하는가" | 방법이 바뀔 때만 |
| **`report` 스킬** | **PR 본문(= 보고서) 형식과 용어 사전** — "밖으로 어떻게 내보내는가" | 형식이 바뀔 때만 |
| `experiment/plan_{mmdd}.md` | **가설 대기열**과 다음 라운드 설계 — "무엇을 할까" | 대기 중 수시로 |
| `experiment/result_{mmdd}.md` | 일지 — "무엇을 했고 무엇이 남았나" | 배정 시 1회 + 판정 후 1회 |

**독자가 다르다는 것이 이 표의 요점이다.** 이 문서와 `experiment/`는 **내가 읽는다** —
약칭을 그대로 쓰고 짧게 쓴다. **PR은 사용자가 읽는다** — 사용자는 대화로 경과를 묻는 대신
GitHub에서 PR을 읽으므로, PR 본문은 **그 자체로 완결된 보고서**여야 한다.
일지의 문장을 PR에 그대로 복사하지 않는다 (11.2절).

`docs/design.md`는 **모델 설계** 문서다(별개). 08-08 실험 기록은 `experiment/result_0808.md`에 동결.

## 1. 역할

| | 하는 일 | 하지 않는 일 |
| --- | --- | --- |
| **팀장 (메인)** | 자원 배분, 실험 설계·우선순위, 브리프, 결과 판정, 병합·커밋, **일지·계획 관리** | 직접 학습을 돌리지 않는다 (자원·컨텍스트 낭비) |
| **팀원 (서브 에이전트)** | 실험 **하나**를 worktree에서 끝까지: 실행 → 대기 → 분석 → **구조화된 보고** | 일지를 쓰지 않는다, 커밋·푸시·PR을 하지 않는다, 배정 안 받은 GPU를 쓰지 않는다 |

**병합은 PR로만 한다** (11절). 채택된 실험은 팀원의 브랜치를 그대로 PR로 올린다 —
파일 복사나 커밋 체리픽은 이력을 끊는다. **병합할 때마다 `design.md` 갱신 팀원을 띄운다.**

**PR 본문은 사용자에게 내보내는 유일한 보고서다** — 형식·용어는 `report` 스킬이 정한다(11.2.1).

**일지는 팀장만 쓴다.** `experiment/`는 gitignore라 worktree에 아예 없다 — 구조적으로 충돌이 없다.

## 2. 냉시동 — 컨텍스트를 비운 뒤 이어서 일하는 법

### 2.0. 기동은 한 마디 — `/round`

새 세션에서 **`/round`** 한 마디면 이 루프가 한 바퀴 돈다(`.claude/commands/round.md`).
반복시키려면 **`/loop /round`** — 간격은 생략한다(자율 페이싱). 완료 감지는 `watch.sh`·
`dispatch.py`가 하므로 짧은 폴링은 토큰 낭비다.

커맨드 본문에는 **상황이 없다.** 상황은 전부 `STATE.md`에서 읽는다 — 그래야 오늘 써도
다음 달에 써도 같은 프롬프트다. 절차·정지 조건·경계만 커맨드에 둔다.

**이 루프는 컨텍스트를 자주 비우는 것을 전제로 설계됐다.** compact로 질질 끌지 않고,
거의 clear 한 뒤 **딱 두 파일**을 읽어 복원한다.

```
① 이 문서 (SKILL.md)        — 방법·규칙·자원
② experiment/STATE.md       — 현재 상태 (80줄 이내)
```

**그 둘로 충분해야 한다.** 부족했다면 그건 STATE.md가 부실한 것이므로 즉시 보강한다.
`result_{mmdd}.md`는 **기본적으로 읽지 않는다** — 특정 과거 실험의 근거가 필요할 때만 펼친다.

복원 직후 실행:

```bash
cat experiment/STATE.md                                # 상태 (유일한 필독 일지)
bash .claude/skills/improve-loop/resources.sh          # 지금 무엇이 돌고 있나
git log --oneline -3 && git status --short             # 최신 main인가
```

- STATE.md의 **"다음 행동"** 한 줄이 곧 지금 할 일이다.
- **"확정된 사실"에 있는 것을 다시 검증하지 않는다.**
- 필요하면 `pytest tests/ -q`·`gh pr list`를 덧붙인다. 매번 할 필요는 없다.

### 컨텍스트를 비우는 시점

> **`/clear`·`/compact`는 사용자만 실행한다. 팀장은 비우는 시점을 고를 수 없다.**
> 대신 컨텍스트가 차면 **자동 압축이 알아서 일어나고, 그 요약에는 손실이 있다.**
> 그러므로 팀장이 통제할 것은 *언제 비우는가*가 아니라 **비워져도 잃을 것이 없는가**다.

| 시점 | 할 일 (전부 팀장이 스스로 할 수 있는 것) |
| --- | --- |
| **실험을 띄운 직후** | STATE.md 갱신 → 감시자 기동 (대기 중엔 컨텍스트가 필요 없다) |
| 50% 도달 | 진행 중인 실험의 수치·상태를 전부 일지로 밀어낸다 |
| 판정 직후 | 결과를 `result_{mmdd}.md`에 적고 STATE.md 갱신 |

**언제든 압축이 일어날 수 있다고 가정하고 STATE.md를 항상 최신으로 둔다.** 이것이 유일한 안전장치다.
정말로 깨끗한 재시작이 필요하면 **사용자에게 `/clear`를 요청한다** — 요청 전에 STATE.md부터 갱신한다.
무인 장기 운영은 `/loop`(사용자가 1회 기동)로 매 iteration을 새 턴처럼 받는다.

## 3. 자원 원장 — 4 GPU / 32 CPU / 251 GB

> **GPU는 끝까지 쓴다. CPU·메모리는 여유를 남긴다.**
>
> 이 기계는 사람이 같이 쓴다 — 원격 데스크톱·에디터·Claude가 **같은 CPU** 위에서 돈다.
> 사용자가 md 파일을 여는 것이 느려지면 안 되므로 CPU·RAM은 절반쯤 비워 둔다.
> **반면 GPU는 사람이 쓰지 않는다. 4장을 놀리지 말고 꽉 채운다** — 슬롯이 비면 즉시 채운다.
> 즉 "자원을 아낀다"가 아니라 **"CPU만 아끼고 GPU는 최대로"** 다.

| 자원 | 배분 규칙 |
| --- | --- |
| **GPU 슬롯 4** | **최대한 채운다.** U arm 1개 = 1슬롯. F = 4슬롯(배타적). D = 0슬롯 |
| **CPU 32코어** | **코어를 미리 떼어 둔다** — `cfg.cpu.reserved_cores`(기본 10)만큼은 항상 사람 몫. 내 프로세스는 `0-21`에만 붙는다. 부하 숫자를 쫓지 말고 **내 예산(22코어) 안에 있는지**를 본다 |
| **우선순위** | 내가 띄운 모든 무거운 프로세스는 **`nice -n 15`** — 대화형이 항상 앞선다 |
| **RAM 251 GB** | **사용량 ≤ 160 GB (약 2/3)**. 남는 것은 페이지 캐시로 두어 파일 열기를 빠르게 |
| **VRAM 24 GB/장** | 한 장에 학습 하나. 예측 덤프를 얹을 때만 `--memory-fraction 0.22` |

**워커 예산 (합쳐서 16을 넘기지 않는다)**

| | 워커 |
| --- | --- |
| U arm 1개 | `num_workers` **x 2** — train/val 데이터로더가 각각 풀을 만든다. `=4`면 arm당 8, 4 arm = **32** (부하 18.6 실측, 상한 초과). **4 arm을 돌리려면 `num_workers=2`** (합 16) |
| F 실행 | 8/rank × 4 = 32 → **F를 돌릴 때는 D 트랙을 아예 띄우지 않는다** |
| D 트랙 | **학습 중이면 `--workers 2` + `OMP_NUM_THREADS=2`** (그 조건에서 부하 +2 이하 실측). `--workers 4`는 학습 중 상한을 넘겼다(16.8). 학습이 없을 때만 8까지 |

### 3.0. CPU 예산은 config가 정한다 (`cfg.cpu`)

**부하 숫자를 한 번 찍어 여유를 판단하지 않는다** — 같은 4 arm이 5.7~18.6을 오간다(학습 단계에
따라). 대신 **쓸 코어를 미리 떼어 둔다.** `CpuConfig`가 단일 출처다.

| 필드 | 뜻 |
| --- | --- |
| `torch_threads` (기본 2) | 프로세스당 intra-op 스레드. **이걸 안 걸면 torch가 32코어를 다 잡는다** |
| `interop_threads` (기본 1) | 프로세스당 inter-op 스레드 |
| `reserved_cores` (기본 10) | 사람 몫으로 남길 코어. 학습은 나머지(0~21)에만 붙는다 |
| `cores` | `"0-21"`처럼 직접 지정. 비면 `reserved_cores`로 계산 |

`stella/train/train.py`와 `scripts/eval_decode.py`가 진입 직후 `CpuBudget.apply()`를 부른다.
**코어 친화도는 자식이 물려받는다**(데이터로더 워커 포함).

이미 돌고 있는 프로세스에 뒤늦게 걸려면:
```bash
for pid in $(pgrep -f "stella.train.train|run_experiments.py"); do taskset -cp 0-21 $pid; done
```

### 3.1. 반드시 `nice`로 띄운다

```bash
nice -n 15 .venv/bin/python -m stella.train.train ...
nice -n 15 .venv/bin/python scripts/eval_decode.py --workers 4 ...
```

이미 돌고 있는 것을 뒤늦게 내리려면:
```bash
for pat in "stella.train.train" "run_experiments" "eval_decode" "tune_decoder" "dump_predictions" "pt_data_worker"; do
  for pid in $(pgrep -f "$pat"); do renice -n 15 -p $pid >/dev/null 2>&1; done
done
```
**실측 효과**: 부하 18.6 → 10.6, 대화형 반응성 즉시 회복. 학습 처리량 손실은 거의 없었다
(GPU 대기가 대부분이라 nice가 낮아도 GPU를 계속 먹인다).

### 3.2. 실측 (배분 근거)

| | 값 |
| --- | --- |
| U arm (10에폭, **4 arm 동시**) | VRAM 13 GB · **4.3 h** (U1_ref 06:19→10:37 실측). 무거운 변형(dilate5·topk6000)이 섞이면 **5.2 h** (E08). ~~2.5 h~~는 틀린 추정이었다 |
| F 실행 (4-GPU DDP) | VRAM **17 GB/장** · 약 10 h → 다른 학습을 못 얹는다(OOM 실측) |
| U arm 4개 (`num_workers=4`) | 부하 **18.6** — 상한 초과. 실제 워커가 arm당 8이라 합 32다. → **`num_workers=2`로 돌린다** |
| F 학습 + D 16워커 | 학습 2.4 → **1.53 it/s** (겹치면 손해) |
| GPU 예측 덤프 | 23초 · `--memory-fraction 0.22`면 학습 중에도 안전 |

### 3.3. 과부하 대응 — 즉시 조치

**부하 > 16**이면 그 자리에서 줄인다. 나중으로 미루지 않는다.

1. **`renice 15`** 를 전부 다시 건다 (가장 싸고 즉효).
2. **D 트랙부터 중단**한다 — 몇 분이면 끝나는 일이라 언제든 다시 돌릴 수 있다.
3. 그래도 높으면 **U arm을 하나 줄인다**(슬롯을 비우고 대기열로 되돌린다).
4. 중단은 실패가 아니다. 일지에 **"연기"** 로 적고 다음 라운드에 다시 올린다.

**사용자가 느리다고 하면 위 1·2를 먼저 하고 나서 원인을 조사한다.** 조사가 먼저가 아니다.

## 4. 실험 단위

| 단위 | 규격 | GPU | 소요 | 쓰임 |
| --- | --- | --- | --- | --- |
| **D** | 저장된 예측을 CPU에서 디코딩만 · **1,000장 이상** | 0 | 분~시간 | 디코더 파라미터·알고리즘 |
| **U** | train 3,000 · **val 700** · 10 에폭 (`configs/unit.py`) | 1/arm | 5~9 h | 손실·아키텍처·증강·하이퍼파라미터 |
| **F** | train 8,979 · **val 전체 1,282** · 40 에폭 | **2** | ~30 h | 기준선, 최신 성과 검증 |

**★ 표본 크기는 타협하지 않는다 (사용자 지시 08-18).** 판정 밴드를 ±2%로 좁혔으므로 표본이
작으면 판정이 표본 잡음을 쫓게 된다. D 트랙 캐시는 **1,000장 이상**으로 뜨고(`gt_val_full`·
`F01_val_full` = 1,282장), U 규격 검증은 **val의 절반 이상(700장)**, F 규격은 **전체**를 쓴다.
"장수를 줄여 빨리 돌리는" 선택지는 없다 — 느리면 병렬로 돌리지 표본을 깎지 않는다.

- U 규격 근거: 표본은 **균등 간격** 추출(앞에서 자르면 지역 편향), `accumulate=4`(짧은 실행에서는
  step 수가 곧 학습량), `warmup=300`, seed 고정.

### ★★ GPU 배분 — **2장은 항상 F 규격에 준다** (사용자 지시 08-18)

**GPU를 놀리는 것도, F 실험을 아끼는 것도 잘못이다.** 기본 배치는 이렇다:

| GPU | 무엇 | 왜 |
| --- | --- | --- |
| **0·1** | **F 규격 상시 가동** — 최신 main 으로 전체 학습 | 지금까지의 성과가 전체 데이터에서도 성립하는지 **항상** 검증 중이어야 한다 |
| 2·3 | U 규격 arm 2개 (또는 D 트랙) | 새 가설을 계속 시험한다 |

- **사람 승인을 기다리지 않는다.** F 실행 착수는 이제 자율 판단이다.
- F 가 끝나면 **바로 다음 F 를 띄운다** — 그동안 병합된 변경을 얹어서. 비어 두지 않는다.
- 2장으로 돌리므로 유효 배치를 맞추려면 `train.accumulate` 를 **32**로 (4장일 때 16).

```bash
CUDA_VISIBLE_DEVICES=0,1 .venv/bin/python -m stella.train.train --config configs.base \
  --tag F02_<무엇을검증> --override train.devices=2 train.accumulate=32 \
  train.epochs=40 data.num_workers=2
```

- U arm 은 2장만 쓰므로 **한 라운드 arm 수를 2개로 잡는다**(대조군 + 변형 1). arm 이 더 필요하면
  두 라운드로 나눈다. **F 를 멈추고 4장을 U 에 몰아주지 않는다.**

**D 트랙** — 학습과 디코딩을 분리해 GPU 없이 디코더를 최적화한다.

```bash
scripts/dump_predictions.py   # 체크포인트 또는 --source gt → 희소 캐시 (샘플당 ~0.4 MB)
scripts/eval_decode.py        # 한 축 스윕 / 단발.  --set 은 점 없으면 decode, 있으면 전체 경로
scripts/tune_decoder.py       # 여러 축 좌표 하강 (비용이 곱이 아니라 합)
```
변형을 넣었으면 **GT 주입 캐시로 회귀 확인**부터 한다 — 천장이 깨지면 그 변형이 틀린 것이다.
**디코더 파라미터를 고를 때도 천장을 같은 표에서 함께 잰다** — 모델 점수를 올리면서 천장을
깎는 설정이 실제로 있었다(꺾임각 20도가 천장을 0.98 → 0.78 로 깎았다).

## 5. 동시 실행 규칙

**"한 실험 = 가설 1개"는 실험 *안*의 규칙이다.** 실험 안에서 grid search는 금지 —
arm은 같은 가설의 강도/변형이고 대조군을 포함한다.

**서로 독립인 실험은 얼마든지 동시에 돌린다.** 독립 = 건드리는 하위 시스템이 겹치지 않는다.
- 예: `손실 가중치`(U) + `디코더 파라미터`(D) + `백본 교체`(U) → 독립. 동시 가능.
- 예: `손실 가중치 A` + `손실 가중치 B` → 겹친다. 하나로 합쳐 arm 강도로 만든다.
- 굳이 겹치는 것을 병렬로 돌리려면 **각자 자기 대조군을 포함**해야 한다.

## 6. worktree 준비 — 팀원을 띄운 **직후** 확인 (실측으로 걸린 함정)

```bash
git worktree list          # 전부 최신 커밋에 있는가?
```

1. **엉뚱한 커밋에서 갈라질 수 있다.** 실제로 한 팀원이 3커밋 전에서 갈라져
   `decode/cache.py`·`eval/cellstat.py`·`configs/unit.py`가 통째로 없었다.
   → `git -C <worktree> reset --hard <최신>` 후 팀원에게 알린다.
   **그래서 팀원을 띄우기 전에 항상 먼저 커밋한다.**
2. **`.venv`가 없고, editable 설치가 격리를 뚫는다.** `ln -sfn <메인>/.venv <worktree>/.venv`.
   `python scripts/foo.py`로 실행하면 `import stella`가 **메인 저장소 코드로 잡힐 수 있다** —
   팀원이 남의 코드를 시험하게 된다. → 브리프에 `export PYTHONPATH=$(pwd)` 필수.
3. **팀원은 `uv sync`·`pip install`을 절대 실행하지 않는다.** `.venv`가 **공유**라,
   worktree에서 `uv sync`를 돌리면 editable 설치 포인터가 그 worktree로 바뀌어
   **돌고 있는 다른 학습까지 남의 코드를 쓰게 된다.** 실제로 한 팀원이 이걸 실행했다.
   → 브리프의 규칙에 명시하고, 보고를 받으면 메인에서 `import stella` 경로를 확인한다.

## 6.5. **완료 감지 — 자원을 놀리는 1순위 원인**

> **실측 실패 3회.** 밤새 GPU 4장이 10시간, 그리고 **12시간 놀았다.** 매번 학습이나 덤프가
> 끝났는데 아무도 깨우지 않았다. 자원을 놀리는 가장 흔한 원인은 잘못된 실험이 아니라
> **끝난 줄 모르는 것**이다.

### ★ 규칙 0 — 긴 작업은 **그 명령 자체를 백그라운드 태스크로 띄운다**

`nohup ... &` 로 띄우면 하네스가 그 프로세스를 추적하지 못한다. 그러면 완료를 알기 위해
**별도 감시자**가 필요해지고, 그 감시자가 깨지면 조용히 멈춘다. 실제로 3회 실패 중 마지막이
그것이었다 — 즉석에서 만든 `while pgrep -f dump_many; do sleep 15; done` 이 **자기 명령줄을
매칭해 무한 루프**에 빠졌고, 종료하지 않았으니 알림도 없었다.

`run_experiments.py` · `dump_many.py` · `rejudge.py` · `gate.py` 는 **전부 끝날 때까지
블록한다.** 그러므로 `run_in_background: true` 로 그냥 띄우면 **종료가 곧 알림**이다.
감시자도, 감시자의 버그도 존재할 수 없다.

```bash
# O — 명령 자체가 백그라운드 태스크. 종료 = 알림
.venv/bin/python scripts/run_experiments.py --round E21 --arms ...   # run_in_background: true

# X — 하네스가 못 보는 곳으로 보내고 따로 감시한다. 감시가 깨지면 끝난 줄 모른다
nohup .venv/bin/python scripts/run_experiments.py ... &
```

`nohup` 은 **세션이 끝나도 살아야 하는 것**(디스패처)에만 쓴다.

### ★ 규칙 1 — 기다릴 때 `pgrep -f <패턴>` 을 쓰지 않는다

`pgrep`/`pkill`/`ps ... -f` 는 **내 명령줄까지 센다.** 패턴이 명령줄에 들어 있으면 조건이
영원히 참이다. 죽일 때·셀 때는 이미 규칙이 있었는데 **기다릴 때** 같은 실수를 했다.

```bash
while kill -0 "$PID" 2>/dev/null; do sleep 20; done   # O — 숫자 PID는 자기를 못 매칭한다
while pgrep -f my_script >/dev/null; do sleep 20; done # X — 무한 루프
```

`watch.sh` 는 `$1 ~ /^python/` 로 명령 **이름**을 걸러 자기 자신을 매칭하지 않는다.
직접 만들지 말고 이것을 쓴다.

### ★ 규칙 2 — **"알림이 오면 하겠다"로 턴을 끝내지 않는다**

알림에 작업 진행을 의존시키면, 알림 장치가 깨졌을 때 조용히 멈춘다. 턴을 끝내기 전에
**지금 할 수 있는 독립적인 일이 남아 있는지** 본다. 남아 있으면 그걸 한다.
정말 기다릴 것밖에 없을 때만 기다리고, 그때는 규칙 0을 지켰는지 확인한다.

**그리고 다음 턴의 첫 행동은 언제나 "지금 실제로 무엇이 돌고 있는가"를 재는 것이다** —
알림을 못 받았다는 사실 자체는 아무것도 알려주지 않는다.

### 감시자 (규칙 0을 못 쓰는 경우에만)

**둘 중 하나를 건다.** 대기열이 차 있으면 디스패처가 낫다 — 깨어날 사람이 없어도 스스로 채운다.

**둘 중 하나를 건다.** 대기열이 차 있으면 디스패처가 낫다 — 깨어날 사람이 없어도 스스로 채운다.

```bash
# (A) 디스패처 — 큐를 소비한다: 자원 대기 → 실행 → 판정 → 일지 → 다음
nohup setsid nice -n 15 .venv/bin/python scripts/dispatch.py &

# (B) 감시자 — 자원이 비면 종료하고, 그 종료 알림이 나를 깨운다
bash .claude/skills/improve-loop/watch.sh        # run_in_background: true 로 띄운다
```

`dispatch.py`는 **실험 실행과 기록까지만** 한다 — 커밋·푸시·PR·병합·삭제는 하지 않는다.
판단이 필요한 사건(채택 발생 · 큐 소진 · 연속 2라운드 무소득 · 가드 장기 위반)에서
멈추고 종료하며, 그 종료가 알림이 된다.

`watch.sh`는 **학습·D트랙 프로세스가 0이고 GPU 4장이 모두 비는 것**을 연속 3회(3분) 확인하면
종료하면서 최근 끝난 실행 목록을 찍는다. 부분 완료(arm 하나만 끝남)에는 반응하지 않는다 —
슬롯이 한 장만 비는 것은 다음 실험을 올릴 만한 사건이 아니기 때문이다.

**감시자가 알려오면 즉시**: ① `summarize_runs.py`로 판정 → ② 대기열 최상단을 올린다 →
③ 다시 감시자를 건다. **이 세 가지가 한 묶음이다.**

**팀원(서브 에이전트)의 완료**는 별도 알림이 자동으로 온다 — 감시자가 필요 없다.
단 팀원이 **백그라운드로 띄우고 멈추면** 그 알림은 "작업 완료"가 아니라 "턴 종료"일 뿐이다.
그래서 브리프에 **"포그라운드로 끝까지 기다려라"** 를 넣는다 (7절 규칙).

**긴 실행(F 규격 10시간)** 은 감시자만으로 부족할 수 있다. 중간 점검이 필요하면
`ScheduleWakeup`(있으면) 또는 `/loop` 로 주기적 깨우기를 함께 건다.

## 7. 팀원 브리프 양식

`Agent` 툴 + `isolation: "worktree"` + 백그라운드. worktree에는 `docs/`·`experiment/`·`.claude/`가
없으므로(전부 gitignore) **프롬프트가 유일한 맥락이다.**

```
[실험 ID] E12 — 무엇을 시험하는가 (한 줄)

## 배경 (팀원이 모르는 것만, 5줄 이내)
- 기준점: 천장 F1 0.976(GT 주입), 현재 최고 F1 0.199(REF-F)
- 이 실험에 필요한 사실만

## 가설
"X를 바꾸면 지표 Y가 Z 방향으로 움직이고, 그 결과 f1/coverage가 개선된다"

## 배정 자원
- GPU: 1,2 (이 두 장만. CUDA_VISIBLE_DEVICES 고정) / CPU: --workers 6 이하

## 시작 전 (반드시)
export PYTHONPATH=$(pwd)
.venv/bin/python -c "import stella; print(stella.__file__)"   # worktree 경로여야 한다

## 실행
.venv/bin/python scripts/run_experiments.py --round E12 --gpus 1,2 --arms "..." "..."

## 보고 형식 (반드시 이 항목들)
1. 실행 폴더 경로 (arm별)
2. 지표 표: f1 / coverage / frag + 가설이 지목한 셀 지표 (마지막 3에폭 평균)
3. 가설이 맞았는가 — 지목한 지표가 예측대로 움직였는가
4. 코드를 고쳤다면 어떤 파일을 왜. 아니면 "config만"
5. 예상 못한 관찰

## 규칙
- **실행은 포그라운드로 끝까지 기다린다.** 백그라운드로 띄우고 턴을 끝내지 마라 —
  그러면 결과를 못 보고 멈춘다. 오래 걸리면 `timeout`을 넉넉히 주고 그대로 기다려라.
- 배정받은 GPU만 쓴다. 코드 수정은 worktree 안에서만.
- **커밋·푸시·PR을 하지 않는다** — 채택되면 팀장이 네 브랜치를 그대로 PR로 올린다.
  변경은 worktree에 그대로 두고, 무엇을 왜 고쳤는지 보고에 적어라.
- **`uv sync`·`pip install` 금지** — .venv는 공유라 돌고 있는 다른 실험을 망친다.
- 끝나면 pytest 로 회귀 확인. 결과를 미화하지 않는다. 수치는 실제 출력에서 가져온다.
- **다른 실행에서 나온 숫자와 비교할 때는 체크포인트·표본이 같은지 먼저 확인**한다.
```

**진척이 없으면 회수한다.** 팀원이 **보고 없이 2회 이상 멈추면** 그 일을 팀장이 인수한다.
실제로 한 팀원이 백그라운드 작업을 띄우고 멈추기를 5회 반복해 토큰 10만을 쓰고도 보고가 0건이었다.
D 트랙처럼 **명령 몇 줄로 끝나는 일은 위임 비용이 실행 비용보다 크다** — 처음부터 팀장이 한다.
위임은 ① 오래 걸리는 학습, ② 맥락을 많이 먹는 조사·분석, ③ 코드 변경이 필요한 실험에 쓴다.

**보고를 그대로 믿지 않는다.** 팀원의 *측정*은 대개 정확하지만 *해석*은 틀릴 수 있다.
실제로 한 팀원이 자기 측정치(에폭 11)를 브리프에 적힌 다른 시점 수치(에폭 39)와 비교해
"지표 정의가 다르다"는 잘못된 결론을 냈다 — 실은 **에폭이 달랐을 뿐**이고, 그 팀원의 값은
같은 에폭의 내 로그와 정확히 일치했다. **수치는 받고 해석은 팀장이 다시 한다.**

**팀원 수 = 빈 GPU 슬롯 + CPU 여유.** 놀리지 않는 것이 원칙이되, 겹치는 가설을 억지로 만들지는
않는다 — 그럴 땐 D 트랙이나 분석·회귀 검증을 시킨다.

## 8. 관측 ① — **손실 균형이 먼저** (지표보다 앞선다)

```bash
.venv/bin/python scripts/loss_balance.py --run <직전 실행>
```

**손실마다 계산식이 달라 스케일이 크게 다르다. 한 항이 너무 커지면 다른 부분이 학습되지 않는다.**
균형이 깨져 있으면 "어느 셀 지표가 나쁜가"를 따지는 것이 무의미하다 — 그 항은 애초에 학습될
기회를 받지 못했다.

**A. 스케일 균형 — 10배 이내.** 안정화 후(마지막 3에폭 평균) **가중 손실의 최대/최소 ≤ 10배**.
로그 손실은 **가중치 적용 전 원시값**이므로 `config.json`의 가중치를 곱해서 봐야 한다(도구가 한다).
`[위반]`이면 그 라운드 1순위 가설은 손실 균형이다.

**B. 진단 기반 가중.** 그 다음 셀 지표가 목표에 못 미치는 항의 가중치를 올린다.

| 손실 항 | 담당 셀 지표 | 목표 |
| --- | --- | --- |
| `heatmap` | `heat_recall` | ≥ 0.90 |
| `class` | `class_acc` | ≥ 0.80 |
| `coord` | `coord_err_px` | ≤ 1.00 |
| `end` | `end_recall` | ≥ 0.70 |
| `exist` | `exist_pos − exist_neg` (판별력) | ≥ 0.50 |
| `dir` | `link_ok` | ≥ 0.99 (아래 근거) |

**함정 둘**
1. **작은 손실 ≠ 굶주린 손실.** 이미 수렴해서 작을 수도 있다. 반드시 담당 셀 지표와 함께 본다.
   실측: `coord`는 최대 대비 1/33이지만 0.84 px로 **수렴**, `end`는 1/4.9인데 재현율 0.31로 **미달**.
2. **전 항목을 똑같이 올리는 것은 아무것도 안 하는 것과 같다**(균일 스케일 = lr 변경).
   달성도에 **반비례**해서만 올린다 — 50%면 2배, 99%면 1.01배, 한 번에 3배 초과 금지.

## 9. 관측 ② — 지표 3층

**"왜 나빠졌는가"에 답하지 못하는 지표는 지표가 아니다.**

**층 1 · 손실** `train|val/{heatmap/focal, self_slot/{class,coord,end}, conn/{exist,dir,match_ambiguity}}`
— 최적화가 도는지만 본다. **판정 근거로 쓰지 않는다.**

**층 2 · 셀 단위 진단** (`stella/eval/cellstat.py`) — 모델 출력이 셀 단위로 얼마나 맞는지.
전부 GPU 텐서 연산이라 비용이 없다.

| 지표 | 나쁘면 |
| --- | --- |
| `heat_recall` / `heat_precision` | 시작부터 선을 놓친다 / 디코더에 가짜 정점이 쏟아진다 |
| `heat_pos`·`heat_neg` | 임계 무관 확률 평균 — "순위가 나쁜지 임계가 틀린지" 구분 |
| `class_acc` / `class_fg` | 정확한 종류 / **배경이 아니라고 본 비율**. 디코더는 `argmax≠0`만 쓰므로 둘을 갈라 봐야 한다 |
| `class_bg_recall` | 거짓 양성 셀을 배경으로 거르는가 → 환각 조각 |
| `coord_err_px` | RMS 횡오차 |
| `end_recall`·`end_precision`·`end_pos`·`end_neg` | precision 낮음 = 중간에서 멈춤 = 조각남 |
| `dir_err_deg`(mean/p90) · `exist_pos`·`exist_neg` | 링크 실패 / 존재 판별 실패 |
| **`link_ok`** | GT 분기 중 예측 방향이 정렬 게이트 안에 든 비율 = **사슬이 이어질 확률** |
| **`chain_expect`** | `1/(1−link_ok)` — 링크 실패까지의 기대 길이 |

> **`link_ok` 목표가 0.99인 근거.** GT 사슬 평균이 **48.2셀**이라 사슬 하나가 온전하려면 링크가
> 47번 연속 성공해야 한다. 선당 기대 조각 ≈ `1 + 47(1 − link_ok)`.
> **0.99 → 1.5조각, 0.95 → 3.4, 0.90 → 5.7.** 0.5는 "절반 맞다"가 아니라 "두 셀마다 끊긴다"는 뜻이다.

**층 3 · 인스턴스 + 디코더 진단** — `val/inst/*` + `val/dec/*`(`stella/decode/stats.py`).
`chains_per_img` · `chain_len` · `stop_{end,nocand,exist,slotused}` · `purity_reject` · `vertex_used`.

**정지 사유 분포가 곧 개선 지시서다.** 그리고 **정지 사유가 지목하지 않은 축은 건드려도 소용없다.**

**★★ 어떤 값을 실측으로 고쳤으면, 그 값을 전제로 정해진 다른 값을 전부 다시 잰다.**
`radius`를 2 → 24로 고친 뒤 이것을 하지 않아 **세 번** 당했다.

| 전제 위에 정해졌던 것 | radius 2에서의 판정 | radius 24에서 다시 재니 |
| --- | --- | --- |
| `exist_thresh` | "`stop_exist` 0.008 — 병목 아님" | **0.268. 사슬 27%가 여기서 끊긴다** |
| `w_dist` (거리 항) | "폐기 — 간선 정확도 0.985→0.953" | **0.03에서 f1 +28%, precision +60%** |
| `DISTANCE_TIEBREAK=1e-3` | "반경 2에서 최대 0.004라 동률만 가른다" | 최대 0.034 — **여전히 거리를 안 본다** |

세 번째 것이 특히 나쁘다: **모듈 상수로 박혀 있어 스윕 대상에조차 오르지 않았다.**
→ **비용 함수·게이트에 들어가는 상수는 전부 config로 뺀다.** 스윕할 수 없는 값은 검증되지 않는다.

**★ 정지 사유 분포도 설정이 바뀌면 통째로 뒤집힌다 — 축을 고를 때마다 다시 잰다.**
실측: radius 2에서는 `stop_exist`가 0.008이라 "그 게이트는 사슬을 멈춘 적이 없다"고 적었고,
그 메모 때문에 08-11 게이트 스윕에서 `exist_thresh`를 **후보에서 아예 뺐다**.
그런데 radius를 32로 키우자 **`stop_exist` 0.008 → 0.268**이 됐다(사슬의 27%가 여기서 끊긴다).
**어떤 파라미터를 고치면 그것이 가리고 있던 다른 축이 되살아난다.
"효과 없음"은 영구 판정이 아니라 그때 설정에 한한 판정이다** — 판정문에 **설정을 함께 적는다.**

**읽는 순서 (상류부터).** 상류가 깨져 있으면 하류를 고쳐도 안 오른다.
`heat_recall → class_acc/class_fg → link_ok, end_precision → dec/stop_* → frag → f1`

**핵심 대조** `chain_expect` vs 실제 `dec/chain_len` — 벌어져 있으면 **디코더**가, 비슷하면 **모델**이 병목.

## 10. 판정 규칙

1. **마지막 3 에폭 평균**으로 비교한다 (단일 에폭은 크게 튄다).
2. 주 지표 3개: **`f1` · `coverage` · `frag`.**
   - **`correctness`는 판정에 쓰지 않는다** — 실측상 차선 간 거리의 중앙값이 버퍼 ρ=12 px와
     **정확히 같아서**, 이웃 차선 위의 예측도 정답으로 세어진다(전형적 차선의 길이 절반이
     남의 버퍼 안에 있다). ρ=8 px는 D 트랙의 보조 엄격 검사로만 쓴다(`--set eval.buffer_rho=8`).
   - **`frag`는 천장 대비로 읽는다** — GT 주입에서도 3.05(strict 2.45)가 나온다. 절대값이 아니다.
3. 상대 **+10% 이상 채택 / ±10% 무효 / −10% 이하 기각.**
4. **가설이 지목한 셀 지표가 실제로 움직였는지** 확인한다. 안 움직였는데 f1만 올랐으면 **보류(재현 필요)**.

## 11. 결과 수령 → 판정 → **PR 병합**

### 11.1. 판정

위 규칙으로 판정한다. **팀원의 수치는 받고, 해석은 팀장이 다시 한다.**

### 11.2. 병합은 PR로 한다 (커밋 체리픽 금지)

**채택된 실험은 팀원의 브랜치를 그대로 PR로 올려 병합한다.** 팀장이 파일을 복사하거나
커밋을 골라 옮기지 않는다 — 그러면 저자·이력·리뷰 기록이 사라지고 무엇이 어떤 근거로
들어왔는지 추적이 끊긴다.

```bash
# 1) 팀원 브랜치를 원격에 올린다 (worktree 안에서 커밋은 팀원이 하지 않았으므로 팀장이 커밋한다)
WT=.claude/worktrees/agent-<id>
git -C $WT add -A
git -C $WT commit -m "<무엇을 왜 + 근거 수치 한 줄>"
git -C $WT push -u origin <브랜치명>

# 2) PR 본문을 파일로 쓴다 (report 스킬 형식) → PR 생성 → 병합 → 로컬 main 갱신
gh pr create --base main --head <브랜치명> --title "<report 2절 형식>" --body-file <본문 경로>
gh pr merge <번호> --merge --delete-branch
git checkout main && git pull --ff-only
```

- config만 바꾼 실험은 병합할 코드가 없다 → 이긴 값을 `configs/schema.py` 기본값에 반영하고
  그 변경만 별도 PR로 올린다.
- **기각**이면 병합하지 않는다. 단 거기서 나온 *도구·테스트*는 값어치가 있으면 따로 PR로 올린다.

### 11.2.1. PR 본문은 **`report` 스킬**이 정한다 — 예외 없다

> **PR을 올리기 전에 `.claude/skills/report/SKILL.md`를 읽고 그 형식으로 쓴다.**
> 용어 설명문은 `.claude/skills/report/glossary.md`에서 **그대로 복사한다.**

**사용자는 PR을 보고서로 읽는다.** 그러므로 PR 본문은 리뷰 메모가 아니라 **그 자체로
완결된 보고서**여야 한다 — 일지·이전 PR·실험 폴더를 열지 않아도 이해되어야 한다.

`report` 스킬의 요구를 여기 요약해 둔다 (**전문은 반드시 읽는다**).

| 반드시 | 내용 |
| --- | --- |
| **용어를 푼다** | 지표·조건·손잡이·규격 이름은 처음 나올 때 `glossary.md`의 문장으로 설명한다 |
| **조건(arm)을 밝힌다** | `alpha075` 같은 이름은 꼬리표일 뿐이다. **무엇을 바꿨나(기본값→값) / 평범한 말로 / 왜 그럴 것이라 봤나**를 표로 먼저 낸다 |
| **표에 열 설명을 붙인다** | 열 이름만 있는 표를 내지 않는다. ↑/↓ 표기를 단다 |
| **숫자에 비교 대상을 붙인다** | 대조군·최고 기록·천장(0.976) 중 최소 하나 |
| **한계를 적는다** | 검증 못 한 것, 이 결론이 적용되지 않는 범위 |
| **다음 실험 계획을 넣는다** | 이 결과가 다음 행동을 어떻게 바꿨나 + 바로 다음 실험 하나 + 대기열 3~5개(순위 근거와 함께). 출처는 `plan_{mmdd}.md`이되 **약칭을 풀어서** 옮긴다 |
| **자가 검사** | `report` 6절 체크리스트를 통과시킨 뒤 올린다 |

**일지 문장을 PR에 복사하지 않는다.** 일지는 내가 읽는 압축 기록이라 약칭투성이다 —
PR은 다시 쓴다. 사전에 없는 용어를 쓰게 되면 **그 PR에서 `glossary.md`에 한 줄을 추가한다.**

### 11.3. 현재 폴더는 항상 최신 `main`

**메인 작업 폴더는 병합 결과를 받는 곳이다.** 실험용 브랜치를 여기 체크아웃해 두지 않는다.
병합할 때마다 `git checkout main && git pull --ff-only` 로 최신을 유지한다.
팀원을 띄우기 전에 이 상태여야 worktree가 최신에서 갈라진다(6절 함정 1).

### 11.4. 병합 직후 — **design.md 갱신 팀원을 띄운다**

**merge가 일어날 때마다** 새 팀원에게 `docs/design.md` 갱신을 시킨다. 설계 문서가 코드보다
뒤처지면 이후 모든 실험의 전제가 틀어진다. 이 갱신도 **PR로** 올린다(11.2와 같은 절차).

```

## 배경

- 방금 PR #<번호>가 main에 병합됐다: <한 줄 요약>

## 12. 일지 (팀장 전용, `experiment/`)

**일지는 다시 읽힐 것을 전제로 쓴다. 길면 읽을 때 토큰을 낭비한다.** 분량 제한을 지킨다.

> **일지에는 `report` 규약을 적용하지 않는다.** 독자가 나 자신이므로 약칭을 그대로 쓴다.
> 대신 **PR을 쓸 때 일지 문장을 복사하지 않고 다시 쓴다** (11.2.1).

| 파일 | 역할 | 분량 | 갱신 |
| --- | --- | --- | --- |
| **`STATE.md`** | **냉시동 진입점.** 기준점 · 돌고 있는 것 · 확정된 사실 · 대기열 · 다음 행동 | **80줄 이내** | **덮어쓴다** (배정·판정 때) |
| `result_{mmdd}.md` | 실험별 상세 근거 | 실험당 **40줄 이내** | 덧붙인다 |
| `plan_{mmdd}.md` | 가설 백로그·다음 라운드 설계 | 제한 없음 | 대기 중 수시로 |

### 쓰는 법 — 표로 쓰고 서술하지 않는다

- **수치는 표에.** 문장으로 풀어 쓰면 3배로 길어지고 비교가 안 된다.
- **해석은 결론만 3줄 이내.** 추론 과정을 적지 않는다 — 결론만 있으면 된다.
- **"확정된 사실"은 한 줄씩.** 근거 실험 ID를 괄호로 붙인다. 그래야 다시 검증하지 않는다.
- 기각도 반드시 남긴다. 남기지 않으면 다음 루프가 같은 실험을 반복한다.
- STATE.md가 80줄을 넘으면 **오래된 "확정된 사실"을 `result_*.md`로 밀어낸다.**

**배정 시 기록** — ID / 가설 1줄 / 조건 표 / 자원 / **볼 지표(미리 고정)**.
**판정 후 기록** — 지표 표 / **판정** 1줄 / 병합 여부 / **다음 수** 1줄.

`STATE.md`의 대기열이 우선순위의 단일 출처다. `plan_*.md`는 그 근거와 설계 초안을 담는다.

## 13. 대기 중에 할 일 (팀장의 본업)

1. **자원 모니터링** (20~30분): 원장 확인 → 과부하면 조절, **슬롯이 비면 즉시 채운다.**
2. **다음 실험 설계** → `plan_{mmdd}.md`. 설계는 **잠정**이다. 새 결과가 오면 반드시 재검토한다.
3. **컨텍스트 관리 — 지키지 않으면 루프가 끊긴다** (실측: 한 세션에서 82%까지 차올랐고,
   그중 **읽기에만 15%(154k)** 를 썼다. 아래는 그때 실제로 저지른 실수들이다.)

   **원칙: 컨텍스트에만 있는 사실을 만들지 않는다.** 새 수치가 나오면 **그 자리에서** 일지에 적는다.
   나중에 정리하려고 미루면 컨텍스트가 먼저 찬다. 일지에 있으면 compact 되어도 무사하다.

   | 하지 말 것 (실제로 한 실수) | 대신 |
   | --- | --- |
   | 지표 전체 표를 매번 다시 뽑아 보기 | 필요한 **열 3~4개만** `awk`/`python -c`로 뽑는다 |
   | 파일 전체 `Read` (2,000줄 문서 등) | `offset`/`limit`, 또는 `grep -n`으로 해당 줄만 |
   | 같은 실행을 여러 번 요약 | 한 번 보고 **일지에 적은 뒤 다시 안 본다** |
   | 편집 후 확인차 다시 읽기 | Edit/Write는 실패하면 에러가 난다. 다시 읽지 않는다 |
   | 긴 명령 출력을 그대로 받기 | `\| tail -N`, `\| head -N`으로 **잘라서** 받는다 |
   | 서브에이전트 transcript 파일 열기 | **절대 열지 않는다.** 완료 보고만 읽는다 |

   - 조사·탐색처럼 맥락을 많이 먹는 일은 **팀원에게 넘긴다** — 그게 위임의 첫 번째 이유다
     (남의 컨텍스트에서 태우고 결론만 받는다).
   - **50% 넘으면**: 진행 중인 모든 실험의 상태·수치를 일지에 밀어 넣는다. 압축은 언제든 온다.
   - **80% 넘으면**: 새 실험을 띄우지 말고 **일지 갱신부터** 한 뒤, 사용자에게 `/clear`를 요청한다.
     컨텍스트가 꽉 찬 채로 판정하면 근거를 잃은 채 결론만 남는다.

**GPU가 비었는데 대기만 하는 상태를 만들지 않는다.**

```

**PR을 올리기 전에 통과시킨다.** 실패하면 병합하지 않는다.

> **학습 중에는 돌리지 않는다.** 부하가 상한(16)을 넘으면 게이트가 **스스로 거부한다**.
> 실측: 학습 4 arm(부하 13)에 게이트를 얹었더니 **부하가 31까지 뛰어 대화형이 느려졌다.**
> 게이트는 급한 일이 아니다 — 슬롯이 빈 뒤에 돌린다. 정말 지금 해야 하면 `--force`.

| 검사 | 무엇을 막나 |
| --- | --- |
| `pytest`·`ruff`·`format` | 계약·린트. 깨지면 아래 수치가 의미를 잃는다 |
| `configs` | `path`+`name` 오타를 학습 몇 시간 뒤가 아니라 여기서 잡는다 |
| **`ceiling_gt`** | **GT를 인코딩해 넣었는데 디코더가 복원 못 하면 그 변경은 틀렸다** (천장 0.976) |
| `model_regress` | 천장(완벽한 입력)만 보면 **약한 입력에서의 퇴행**을 놓친다 |

### 16.1. 게이트는 살아 있어야 한다 — **고정 목록이 아니다**

검사 목록은 코드가 아니라 **데이터**(`gate_baseline.json`)다. 지금까지 배운 실패 양식의 누적이며,
**새로운 방식으로 깨지는 것을 볼 때마다 항목을 하나 더한다.** 14절(새 지표)과 같은 논리다.

- 각 항목의 `why`는 **"이 검사가 어떤 사고를 막는가"** 다. 답할 수 없는 검사는 지운다.
- `since`에 계기가 된 실험 ID를 남긴다 — 왜 생겼는지 모르는 검사는 다음 사람이 지운다.
- **하한은 래칫된다.** 개선이 확정되면 `--update`로 실측의 90%까지 하한을 끌어올린다.
  내리는 방향으로는 자동으로 움직이지 않는다 — 퇴행을 정당화하려면 사람이 손으로 고친다.
- 판정·병합 중 **"게이트가 이걸 못 잡았겠다"** 싶은 것을 발견하면 **그 자리에서** 추가한다.
  나중으로 미루면 다음 사고가 같은 자리에서 난다.

## 규칙 요약

- 코드를 쓰거나 고칠 때는 **`coding` 스킬을 먼저 읽는다** (모듈 400 / 클래스 200 / 함수 30줄, 100자).
- `__init__`은 config를 모른다. 클래스 선택은 `build_instance` 한 곳. 새 하이퍼파라미터는 **반드시 config**.
- 문서·주석·보고는 한국어.
- 실험 하나 = 가설 하나. 여러 실험은 **서로 독립일 때만** 동시에.
- **병합 전에 `gate.py`.** 새 실패 양식을 보면 그 자리에서 게이트에 검사를 더한다.
- **자원을 놀리지 않는다.**
