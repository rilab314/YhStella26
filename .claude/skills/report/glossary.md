# 용어 사전 — 보고서에 붙일 표준 설명문

**이 파일의 용도.** 보고서(PR 본문)에 지표·용어가 나오면, 여기 있는 **"설명" 칸을 그대로
복사해서** PR 안의 「이 보고서에 나온 용어」 표에 붙인다. 매번 새로 풀어 쓰면 PR마다 설명이
달라져서 읽는 사람이 같은 말을 다시 배워야 한다.

**설명문 기준**: 이 프로젝트를 처음 보는 동료가 **한 번 읽고 알아듣는** 수준. 수식을 쓸 거면
반드시 "즉, ~라는 뜻" 을 붙인다.

여기 없는 용어를 쓰게 되면 **먼저 여기에 한 줄을 추가하고** 그 문장을 PR에 쓴다.

## 0. 실험 규격 · 기준점

| 용어 | 설명 (그대로 복사해 쓴다) |
| --- | --- |
| **D 규격 (D 트랙)** | 학습을 하지 않고, 이미 저장해 둔 예측을 **디코더로 다시 잇기만** 하는 실험. GPU가 필요 없고 몇 분이면 끝난다 |
| **U 규격 (단위 실험)** | 아이디어 비교용 짧은 학습. 학습 3,000장·검증 320장·10에폭·GPU 1장, 약 2.5시간. **네 개를 동시에 돌려** 한 라운드를 만든다 |
| **F 규격 (전체 학습)** | 진짜 성적을 내는 학습. 학습 8,979장·40에폭·GPU 4장, 약 10시간 |
| **U 규격 수치와 F 규격 수치는 섞지 않는다** | 데이터량과 배치 크기가 달라 절대값 비교가 성립하지 않는다. U는 U끼리, F는 F끼리만 비교한다 |
| **arm (조건)** | 한 라운드에서 **동시에 돌리는 실험 조건 하나**. 예: "팽창을 5로 키운 조건". 이름(`dilate5` 등)은 폴더 구분용 꼬리표일 뿐이라 **무엇을 바꿨는지 항상 따로 적는다** |
| **대조군 (control)** | 비교 기준이 되는 조건. **아무것도 바꾸지 않고** 같은 규격으로 돌린 실행이다. 다른 arm의 "+22%"는 전부 이 값 대비다 |
| **천장 (ceiling, GT 주입)** | **모델이 완벽하다고 가정했을 때** 나오는 점수. 정답을 그대로 모델 출력 형식에 넣고 디코더만 돌려서 잰다. 현재 F1 **0.9410**(전체 검증셋 1,282장) — 어떤 모델도 이보다 잘할 수 없다. **08-19 에 평가 버퍼를 12 px 에서 3 px 로 좁히면서 0.977 에서 내려왔다** — 옛 버퍼는 옆 차선으로 갈아탄 선도 만점으로 쳤다. **디코더 설정을 바꿀 때마다 같이 재야 한다** — 모델 점수를 올리면서 천장을 깎는 설정이 실제로 있었다 |
| **기준선 (baseline)** | 지금까지의 최고 실측 기록. 이번 변경이 이것을 넘겨야 의미가 있다 |
| **REF-F** | F 규격 기준선 실행. F1 0.199 (2026-08-08) |
| **U1_ref / U2_ref** | U 규격 대조군 실행. 뒤 숫자는 라운드 번호다. 기본값이 바뀌면 옛 대조군은 **비교 기준으로 죽으므로** 새 대조군을 다시 돌린다 |

## 1. 최종 성적 — 선(인스턴스) 단위 지표 (`val/inst/*`)

> **이 묶음이 최종 성적표다.** 예측한 선 하나가 정답 선 하나와 짝이 맞아야 정답으로 센다.
> 짝이 되려면 **차선 종류가 같고**, 예측이 그 정답 선 길이의 **절반 이상**을 덮어야 한다.
> 그래서 긴 선을 중간에 한 번만 끊어 먹어도 0점이다.

| 지표 | 설명 (그대로 복사해 쓴다) | 방향 |
| --- | --- | --- |
| **f1** | **최종 성적.** "정답을 얼마나 많이 찾았나(재현율)"와 "찾은 것 중 몇 개가 진짜였나(정밀도)"를 하나로 합친 점수. 0~1 | 높을수록 |
| **precision (정밀도)** | 예측한 선 중 정답과 짝이 맞은 비율 | 높을수록 |
| **recall (재현율)** | 정답 선 중 짝이 맞은 예측이 있는 비율 | 높을수록 |
| **micro / macro** | micro는 전체 선을 한 통에 넣고 계산한 값(흔한 차선 종류가 지배한다). macro는 차선 종류별로 계산해 평균낸 값(희귀한 종류도 같은 비중) | — |
| **coverage (덮개율)** | 정답 선 전체 길이 중 예측이 덮은 비율. 즉 **놓친 구간이 얼마나 적은가** | 높을수록 |
| **correctness (정확성)** | 예측한 선 하나가 **정답 선 하나 위에 머무는 비율.** 가장 잘 맞는 정답 선 **하나**를 골라 그 선 기준으로만 잰다. 옆 차선으로 갈아탄 예측은 여기서 점수가 떨어진다 — **차선 갈아탐을 보는 유일한 지표다** | 높을수록 |
| **rms (횡오차)** | 예측 선이 정답 선에서 **옆으로 벗어난 거리**의 평균 (픽셀). 1픽셀이 지상 약 13 cm | 낮을수록 |
| **frag (조각남)** | 정답 선 하나를 예측 **조각 몇 개가 나눠서** 덮고 있는가. 1이면 한 번에 온전히 그린 것. **절대값으로 읽지 말고 천장(1.73)과 비교한다** | 낮을수록 |
| **frag_strict** | `frag`와 같되, 그 정답 선을 10% 이상 덮은 조각만 센다. 천장은 1.27 | 낮을수록 |
| **fp_redundant** | 진짜 차선 위에 그렸지만 짝이 안 맞은 **잉여 조각** 수 | 낮을수록 |
| **fp_spurious** | 차선이 없는 곳에 그린 **환각** 수 | 낮을수록 |
| **buffer_rho (평가 버퍼 ρ)** | 예측이 정답과 "같은 자리"라고 인정하는 거리, 현재 **3픽셀**. 실측 차선 간격 중앙값 11.8픽셀의 1/4이다. **옛 값 12픽셀은 간격과 같아서 옆 차선을 삼켰다** | — |
| **차선 갈아탐 (lane switch)** | 예측 선 하나가 어떤 차선을 따라가다 **중간에 이웃 차선으로 옮겨 타는** 현상. 평가 버퍼가 차선 간격만큼 넓으면 지표에 잡히지 않는다 — 2026-08-14에 이것 때문에 성적이 실제의 약 2배로 나오고 있었음이 밝혀졌다 | — |
| **중복 정리 (dedup)** | 같은 차선 위에 **두 번 그려진** 선을 지우거나 끝에서 잇는 후처리. 예측 선의 12.9%가 같은 종류의 다른 선과 2 px 간격으로 나란히 그려진다 — 이웃 차선(간격 11.8 px)이 아니라 같은 차선 위 이중 그리기다. 이 단계를 거치면 0.5%로 내려간다 |
| **머리·꼬리만 자르기 (`dedup_mode="ends"`)** | 중복 정리에서 **자르는 위치를 선의 양 끝으로만 제한하는** 방식. 가운데를 자르지 않으므로 선 하나가 조각으로 갈라질 수 없다(1개 → 1개 또는 0개). 가운데 겹침은 이중 그리기가 아니라 **교차**라서 자르면 안 되는 것이다 |
| **후처리 계약** | 후처리가 **지키기로 정한 규칙** — 지우거나 이미 겹친 선끼리 잇기만 한다. 떨어진 선을 잇지 않고, 없던 선을 만들지 않는다. 그래서 선 개수는 줄기만 한다 |
| **guiding_line (유도선)** | 차선 종류 11가지 중 하나. **선이 아니라 면으로 칠해진 영역**이라 애초에 선으로 찾을 대상이 아니다(2026-08-26 확인). 검증셋 정답 선의 6.2%를 차지한다 |
| **`eval.exclude_classes`** | 성능 계산에서 **특정 차선 종류를 통째로 빼는** 설정. 정답 쪽과 예측 쪽을 둘 다 빼야 같은 판이 되므로, 종류별 점수를 평균에서 빼는 것만으로는 안 된다 |

## 2. 부품별 진단 — 셀 단위 지표 (`val/cell/*`)

> **모델은 이미지를 4픽셀짜리 격자 셀로 자르고, 셀마다 여러 가지를 동시에 예측한다.**
> 최종 성적이 나쁠 때 **어느 부품이 원인인지** 가리려고 부품별로 따로 채점한 것이 이 묶음이다.

### 2-1. 검출 — "이 셀에 선이 있나"

| 지표 | 설명 (그대로 복사해 쓴다) | 방향 |
| --- | --- | --- |
| **heat_recall** | 선이 실제로 지나가는 셀 중 모델이 **찾아낸 비율**. 놓친 셀은 뒤에서 되살릴 방법이 없다 | 높을수록 |
| **heat_precision** | 모델이 고른 셀 중 실제로 선이 있는 비율. **낮아도 괜찮다는 것이 실험으로 확인됐다** — 정밀도를 올린 조건이 오히려 F1을 62% 떨어뜨렸다 | (참고용) |
| **heat_pos / heat_neg** | 선이 있는 셀 / 없는 셀에서 모델이 낸 **평균 확률**. 임계값과 무관하게 "둘을 구분은 하고 있나"를 본다. 둘이 붙어 있으면 그 부품은 죽은 것이다 | pos↑ neg↓ |
| **node_per_img** | 이미지 한 장에서 고른 셀 수. 정답은 장당 평균 1,826개다. 폭증하면 디코더가 가짜 점에 잠긴다 | (감시용) |

### 2-2. 분류 — "무슨 차선인가" (11종)

| 지표 | 설명 (그대로 복사해 쓴다) | 방향 |
| --- | --- | --- |
| **class_fg** | 고른 셀 중 **"배경이 아니다"라고 본 비율.** 여기서 배경이라고 불린 셀은 디코더에게 전달조차 되지 않는다 | 높을수록 |
| **class_acc** | 고른 셀 중 **차선 종류까지 정확히 맞힌 비율.** ⚠️ **분모가 "모델이 고른 셀"이라 조건마다 흔들린다 — 선택 방식이 다른 arm끼리 비교하면 안 된다** | 높을수록 |
| **class_recall** | 분모를 **전체 정답 셀**로 고정한 정확도. 조건이 달라도 비교할 수 있다 | 높을수록 |
| **vertex_recall** | **가장 중요한 셀 지표.** 정답 셀 중 "찾았고 + 배경이 아니라고 본" 비율 = `heat_recall × class_fg`. 즉 **디코더가 이어붙일 재료로 실제로 넘겨받는 점의 비율**이다. 네 조건 실험에서 F1과 상관계수 **+0.994** — 사실상 F1을 결정한다 | 높을수록 |
| **class_bg_recall** | 배경 셀을 배경이라고 제대로 부른 비율 | 높을수록 |

### 2-3. 위치 · 연결 — "선이 어디를 지나 어디로 이어지나"

| 지표 | 설명 (그대로 복사해 쓴다) | 방향 |
| --- | --- | --- |
| **coord_err_px** | 셀 안에서 선의 위치를 얼마나 정확히 짚었나 (픽셀). **이미 수렴했다 (0.84 px)** | 낮을수록 |
| **dir_err_deg** | 다음 셀로 이어지는 **방향의 각도 오차** (도). **이미 수렴했다 (6.2°)** | 낮을수록 |
| **link_ok** | 방향 오차가 20° 이내인 연결의 비율 = **한 칸 잇기 성공률**. 정답 선 하나가 평균 48셀이라 47번 연속 성공해야 온전히 나온다 — **99% 아래면 사실상 의미가 없다** (95%면 선당 3.4조각으로 쪼개진다) | 높을수록 |
| **chain_expect** | 위 성공률로 기대되는 **끊기지 않는 사슬 길이** = 1/(1−link_ok). 정답 평균 48셀과 비교한다 | 높을수록 |

### 2-4. 슬롯 · 끝 — "이 연결이 실제로 쓰이나 / 여기가 선의 끝인가"

| 지표 | 설명 (그대로 복사해 쓴다) | 방향 |
| --- | --- | --- |
| **exist_pos / exist_neg** | 연결이 실제로 있는 슬롯 / 없는 슬롯에서 낸 **평균 확률**. **둘의 차이가 판별력**이다 (현재 0.33, 목표 0.5 이상). 차이가 0에 가까우면 이 부품은 아무것도 구분하지 못하는 것이다 | 차이↑ |
| **end_recall** | 선의 **끝인 셀**을 끝이라고 알아챈 비율. 현재 0.32로 미달 | 높을수록 |
| **end_precision** | 끝이라고 부른 셀 중 진짜 끝인 비율. **낮으면 선이 중간에서 잘린다** | 높을수록 |
| **end_pos / end_neg** | 끝 셀 / 중간 셀에서 낸 평균 확률. 임계값과 무관한 판별력 확인용 | 차이↑ |

## 3. 디코더 진단 (`val/dec/*`)

> **디코더 = 셀들을 실제로 이어 붙여 선을 만드는 프로그램.** 학습하지 않는 규칙 기반 코드다.
> 사슬(chain)이 왜 짧은지를 "멈춘 이유"로 알려준다.

| 지표 | 설명 (그대로 복사해 쓴다) | 방향 |
| --- | --- | --- |
| **chain_len** | 이어붙인 사슬 하나의 평균 길이 (셀). **정답은 평균 48.2셀**이다 | 높을수록 |
| **chains_per_img** | 이미지당 만들어진 사슬 수. 정답 선은 장당 평균 38개 — 이보다 훨씬 많으면 잘게 쪼개졌다는 뜻이다 | 정답에 가깝게 |
| **stop_end** | 사슬이 멈춘 이유 중 **"여기가 선의 끝이라고 판단해서"** 의 비율. 정상적인 종료다 | — |
| **stop_nocand** | 멈춘 이유 중 **"이어갈 다음 점을 못 찾아서"** 의 비율. **이게 높으면 점이 비어 있다는 신호** | 낮을수록 |
| **stop_exist** | 멈춘 이유 중 "연결 슬롯이 꺼져 있어서" 의 비율 | — |
| **stop_slotused** | 멈춘 이유 중 "그 방향을 이미 써버려서" 의 비율 | — |
| **purity_reject** | 만들다가 **차선 종류가 섞여서 버린** 사슬 수 (이미지당) | 낮을수록 |
| **정지 사유가 지목하지 않은 손잡이는 건드려도 소용없다** | 실제로 겪은 교훈이다 — 평균 확률만 보고 임계값을 고쳤다가 헛수고했다. 항상 정지 사유 분포부터 본다 | — |

## 4. 손실 함수 (학습이 줄이려는 값, `train/*` · `val/*`)

> **손실 = 모델이 얼마나 틀렸는지의 점수.** 학습은 이걸 줄이는 방향으로 가중치를 고친다.
> 부품마다 손실이 따로 있고, 전부 더해서 하나로 만든다(`total`).

| 이름 | 설명 (그대로 복사해 쓴다) |
| --- | --- |
| **heatmap** | "이 셀에 선이 있나"를 틀린 정도. **focal loss** — 쉬운 예제(대부분이 배경)의 비중을 자동으로 낮춰 주는 방식이다 |
| **class** | 차선 종류(11종 + 배경)를 틀린 정도. **cross entropy** — 정답 종류에 매긴 확률이 낮을수록 커진다 |
| **coord** | 셀 안에서의 위치를 틀린 정도 |
| **dir** | 연결 방향을 틀린 정도. `1 − cos(각도차)` 라서 **0.048이면 평균 약 18°** 라는 뜻이다 |
| **exist** | "이 연결 슬롯이 실제로 쓰이나"를 틀린 정도 |
| **end** | "여기가 선의 끝인가"를 틀린 정도 |
| **switch_rate** | 손실이 아니라 **감시 값**. 예측 슬롯과 정답 방향을 짝지을 때 그 짝이 흔들린 비율. 높으면 슬롯들이 역할을 나눠 갖지 못한 것이다 |
| **가중치 `w_heat`·`w_class`·`w_coord`·`w_dir`·`w_exist`·`w_end`** | 각 손실을 더할 때 곱하는 배수. **전부 똑같이 2배 하는 것은 아무것도 안 한 것과 같다** (학습률만 바뀐다) |
| **손실 항목끼리는 경쟁한다** | 실측으로 확인됐다 — 클래스 손실 가중치를 2배로 올렸더니 검출 재현율이 0.83→0.77로 내려갔다 |

## 5. 자주 바꾸는 설정 손잡이

> 값을 쓸 때는 **반드시 "기본값 → 바꾼 값"** 형태로 쓴다. 바꾼 값만 쓰면 크기를 알 수 없다.

### 5-1. 모델 · 학습

| 손잡이 | 설명 (그대로 복사해 쓴다) | 기본값 |
| --- | --- | --- |
| **`model.dilate`** | 선이 있다고 고른 셀 주변을 **몇 칸까지 부풀려 함께 후보로 삼을지.** 3이면 3×3. 배경 셀이 섞여 들어오는 대신 놓친 셀을 되살린다 — **실측상 재현율의 주 공급원이다** (끄면 F1이 62% 떨어졌다) | 3 |
| **`model.heatmap_thresh`** | 셀을 후보로 뽑는 **확률 문턱값.** 낮출수록 많이 뽑는다 | 0.3 |
| **`model.select_mode` / `n_topk`** | 셀을 고르는 방식. `thresh`는 문턱값 기준, `topk`는 **확률 상위 K개 고정**(뽑는 개수가 흔들리지 않는다) | thresh |
| **`loss.heatmap.focal_alpha`** | focal loss에서 **"선이 있는 셀"에 주는 비중.** 통상값 0.25는 선이 있는 쪽을 억눌러 재현율을 깎는다 — 이 과제에서는 **놓친 점이 곧 사라진 선**이라 거짓 양성보다 비싸다 | 0.75 |
| **`loss.self_slot.class_freq_power`** | 드문 차선 종류에 **더 큰 가중치**를 주는 세기. 0이면 가중 없음. 희귀 종류 3개가 한 번도 예측되지 않는 문제의 처방이다 | 0.0 |
| **`loss.self_slot.class_bg_weight`** | 배경 클래스에 주는 가중치. 낮추면 배경을 덜 신경 쓴다 | 1.0 |
| **`model.window_size`** | 어텐션이 한 번에 보는 이웃 셀의 범위 (홀수). 크면 멀리 보지만 메모리·시간을 먹는다 | 7 |
| **`data.grid_stride`** | 격자 한 칸이 몇 픽셀인가. 키우면 사슬이 짧아져 잇기가 쉬워지지만 위치 해상도를 잃는다 | 4 |
| **`train.accumulate`** | 몇 번의 미니배치를 모아 한 번 가중치를 고칠지. 크면 배치가 커지는 대신 **가중치를 고치는 횟수가 줄어든다** | 16 (F) / 4 (U) |
| **`model.n_max`** | 한 장에서 고를 수 있는 셀의 상한 | 9500 |

### 5-2. 디코더 (학습 없이 바꿔 볼 수 있다)

| 손잡이 | 설명 (그대로 복사해 쓴다) | 기본값 |
| --- | --- | --- |
| **`radius`** | 다음 점을 **몇 칸(셀) 앞까지 찾아볼지.** 한 칸이 4픽셀이므로 12는 ±48픽셀이다. **크면 이웃 차선을 후보로 집어 갈아탐이 는다** — 실측상 정확성이 반경에 반비례한다(4칸 0.872 → 24칸 0.726) | 12 |
| **`align_thresh`** | 다음 점이 예측 방향과 **얼마나 정렬돼야** 후보로 인정할지 (코사인). 0.95 = 약 18° 원뿔. **각도만 보므로 멀리 있는 후보에게 관대하다** — 같은 "한 차선 옆"이라도 앞 12픽셀이면 45°로 막히고 앞 60픽셀이면 11°로 통과한다 | 0.95 |
| **`max_turn_deg`** | 사슬이 **연속한 두 걸음 사이에 꺾일 수 있는 최대 각도.** 물리적으로 불가능한 꺾임을 막는 안전장치다. **너무 조이면 직선도 끊긴다** — 점 간격이 4픽셀이라 직선 위에서도 방향이 양자화 잡음으로 20°를 넘기 때문이다(20°는 천장을 0.98→0.78로 깎았다) | 45 |
| **`merge_gap`** | 끊긴 조각의 끝이 이만큼 이내면 **이어 붙인다.** 실측 효과는 미미하다(±0.3%) | 0 |
| **`min_points`** | 점이 이보다 적은 예측은 **버린다.** 짧은 허위를 지워 정밀도를 사지만 짧은 진짜 선도 같이 버린다 — 정답 선의 13.3%가 6점 미만이다. **차선 갈아탐과는 무관하다**(정확성이 안 움직인다) | 2 |
| **`opp_thresh`** | 다음 점이 **이쪽을 마주 보고 있어야** 하는 정도. 양방향 합의를 요구한다 | 0.7 |
| **`w_dist`** | 다음 점을 고를 때 **거리에 매기는 벌점의 크기.** 0에 가까우면 디코더가 정렬만 보고 멀리 도약해 한 선이 여러 조각으로 쪼개진다 | 0.03 |
| **`min_class_prob`** | 후보의 차선 종류 확률 하한. 높이면 애매한 점을 안 쓴다 | 0.1 |
| **`exist_thresh` / `end_thresh`** | 연결 슬롯을 켜진 것으로 볼 확률 문턱 / 선의 끝으로 볼 확률 문턱 | 0.3 / 0.5 |
| **`purity_thresh`** | 사슬 안에서 차선 종류가 얼마나 일관돼야 살릴지 | 0.6 |
| **`end_extend`** | 사슬 양 끝을 방향대로 얼마나 연장할지 (셀) | 1.0 |

## 6. 판정 어휘

| 용어 | 설명 (그대로 복사해 쓴다) |
| --- | --- |
| **채택 (adopt)** | 대조군 대비 최종 성적(f1)이 **+10% 이상** 올랐고, 가설이 지목한 지표도 같은 방향으로 움직였다 → 기본값에 반영한다 |
| **무효 (neutral)** | 변화가 ±10% 이내. 오차 범위라 **효과가 없다고 본다** |
| **기각 (reject)** | −10% 이하로 나빠졌다. **가설이 틀렸다는 기록으로 남긴다** — 남기지 않으면 다음에 같은 실험을 또 한다 |
| **보류 (hold)** | 최종 성적은 올랐는데 **가설이 지목한 지표는 안 움직였다.** 우연일 수 있어 다시 확인해야 한다 |
| **지목 지표 (watch)** | 가설이 "이게 움직일 것"이라고 **미리 지정한** 지표. 결과를 보고 나서 고르면 안 된다 |
| **반증 조건** | "이렇게 나오면 가설이 틀린 것"을 실험 **전에** 정해 둔 것 |
| **게이트 (gate)** | 병합 전에 통과해야 하는 자동 검사 묶음. 테스트·문법·천장 회귀·모델 회귀를 한 번에 본다 |
