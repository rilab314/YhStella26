STELLA 개선 루프를 이어서 진행한다. **상태는 파일에서 읽는다 — 이 프롬프트에는 상황이 없다.**

추가 지시(있으면 우선): $ARGUMENTS

## 1. 복원

`.claude/skills/improve-loop/SKILL.md` 와 `experiment/STATE.md` 를 읽는다(이미 컨텍스트에
있으면 다시 읽지 않는다). STATE.md의 **"다음 행동"이 지금 할 일**이다.
**"확정된 사실"에 있는 것은 다시 검증하지 않는다.** `result_*.md` 는 근거가 필요할 때만 펼친다.

## 2. 자원

`bash .claude/skills/improve-loop/resources.sh` 로 확인한다.
부하가 16을 넘으면 **그 자리에서** 낮춘다: `renice 15` 재적용 → D 트랙 중단 → U arm 축소.
조사보다 조치가 먼저다 — 사람이 같은 CPU를 쓴다.

## 3. 상태별 행동

- **슬롯이 꽉 찼다** → 학습을 건드리지 않는다. `scripts/dispatch.py` 또는 `watch.sh` 가
  살아 있는지 확인하고(없으면 다시 건다), 대기 중 본업을 한다: 다음 라운드 설계를
  `experiment/plan_{mmdd}.md` 에, 새 수치는 **즉시** 일지에. GPU를 안 쓰는 D 트랙 작업이
  대기열에 있고 부하에 여유가 있으면 그것을 돌린다.
- **슬롯이 비었다** → ① `scripts/judge_round.py --round <ID> --control <대조군>` 으로 판정
  ② 결과를 `experiment/result_{mmdd}.md` 에 ③ 대기열 최상단을 배정 ④ 감시자/디스패처 재기동.
  **이 넷은 한 묶음이다.** GPU를 놀리지 않는다.
- **채택이 나왔다** → `scripts/gate.py` 를 통과시킨 뒤 브랜치·커밋·PR·병합·pull 까지 진행한다.
  게이트가 실패하면 병합하지 않는다. 병합 후 `docs/` 갱신이 필요한지 확인한다.
- **대기열이 비었다** → 새 가설을 세워 `experiment/queue.json` 과 STATE.md 대기열에 넣는다.
  지배 지표(현재 `vertex_recall`)를 직접 올리는 축을 우선한다. 근거는 plan에 남긴다.

## 4. 게이트를 살려 둔다

게이트는 고정된 검사 목록이 아니라 **지금까지 배운 실패 양식의 누적**이다.
판정·병합 과정에서 **게이트가 못 잡았을 실패**를 발견하면 그 자리에서
`gate_baseline.json` 에 검사를 추가하고 `why` 에 어떤 사고를 막는지 적는다.
개선이 확정되면 `scripts/gate.py --update` 로 하한을 래칫한다.

## 5. 기록

무엇을 했든 끝에 `experiment/STATE.md` 를 **덮어쓴다**(80줄 이내).
압축은 언제든 온다 — **컨텍스트에만 있는 사실을 만들지 않는다.**

## 6. 정지 — 아래면 멈추고 사람에게 보고한다

- 연속 2라운드 채택 0 (그 축은 소진됐다)
- 게이트 실패가 코드 수정으로 풀리지 않음
- 대기열이 비었는데 새 가설의 근거가 약하다
- 아래 "승인이 필요한 것"에 도달

## 경계

**알아서 해도 되는 것**: worktree 생성·정리, 브랜치, 커밋, 푸시, PR 생성·병합, pull,
실험 실행·중단, 일지·계획·큐 갱신, 게이트 검사 추가.

**사람 승인이 필요한 것**: 데이터셋·로그·체크포인트 **삭제**, main 히스토리 재작성(force push),
F 규격(4 GPU·10시간 배타) 착수, 서브 에이전트 기동, DINOv3 게이트.
