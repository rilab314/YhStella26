# 논문 그림·표 생성 스크립트

**그림 하나 = 스크립트 하나, 표 하나 = 스크립트 하나.** 논문에 실릴 모든 그림과 표는
여기 있는 스크립트가 만든다. 손으로 만든 그림·표는 논문에 넣지 않는다 — 실험을 다시 돌리면
반드시 어긋나고, 심사에서 "이 값은 어디서 나왔나"에 답할 수 없다.

설계 근거는 `docs/paper_assets.md`(15절)에 있다. 그림·표의 **내용** 설계는
`docs/paper_outline.md` 3·4절이다.

## 지금 상태

**전부 미구현이다.** 각 파일에는 docstring 으로 설계만 적혀 있다 —
무엇을 그리나 · 왜 필요한가 · 선별 조건 · 정렬 기준 · 입력 · 출력 · 상태.
설계를 하나씩 검토해 확정한 뒤 구현한다.

## 구조

```
stella/paper/         공유 코드 — import 되어야 하므로 패키지 안에 둔다
├── paths.py          출력 경로 단일 출처 · 폴더 단위 덮어쓰기 규약
├── figure_base.py    SampleFigure(샘플 선별형) · PlotFigure(집계형)
└── table_base.py     PaperTable(csv + markdown)

scripts/paper/        진입점 — 산출물 하나 = 파일 하나
├── figures/          figure_01.py ~ figure_14.py
└── tables/           table_01.py ~ table_09.py   (논문 Table I~IX)
```

## 출력은 저장소가 아니라 데이터 작업 폴더에 쌓인다

```
.../Ongoing/2026_stella/paper/
├── figure/figure_01/  001_{타일id}_{점수}.png ...   (최대 100장)
└── table/table_01/    table_01.csv · table_01.md
```

**폴더 단위로 지우고 다시 만든다.** `figure_01` 을 다시 그리면 `figure_01/` 을 통째로
지우고 새로 만든다 — 지난 실행에서 3위였다가 이번에 탈락한 그림이 남아 있으면 안 된다.

논문에 실제로 고른 몇 장만 `docs/figures/` 로 옮겨 커밋한다.

## 그림은 골라서 그린다 (사용자 지시)

데이터 전체를 렌더링해 눈으로 고르지 않는다. 그림마다 **그 현상이 실제로 일어난 프레임만**
정량 조건으로 고르고, 정렬 기준과 **상한 100장**을 둔다. 파일명 앞 세 자리가 순위다.

조건이 100장보다 훨씬 많이 통과하면 조건이 헐거운 것이므로 조건을 조인다.

## GPU 를 쓰지 않는다

입력은 `scripts/dump_predictions.py` 가 떨군 **예측 캐시**다. 학습이 GPU 를 다 쓰는 중에도
그림·표를 만들 수 있다 (CLAUDE.md 의 D 트랙 규약). 학습 중에는 CPU 부하 상한 16 을 지킨다.

## 갈래별 대응

| 갈래 | 그림 |
| --- | --- |
| 샘플 선별형 (최대 100장) | 1 · 4 · 7 · 9 · 11 · 12 |
| 집계형 (1장 + csv) | 2(c) · 3 · 5(c) · 6 · 8(c) · 10 · 13 · 14 |
| 개념도 (그리기 도구) | 2(a,b,d) · 3의 도형 · 4의 설명 글상자 · 5(a,b) · 7의 도형 · 8(a,b) |

개념도도 **그림에 적을 숫자는 코드로 뽑는다** — 손으로 적으면 config 를 바꿨을 때
그림이 조용히 틀린 값을 갖게 된다.
